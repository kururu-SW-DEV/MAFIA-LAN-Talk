# v3.0 텔레그램풍 재설계 + 단체대화방 + 알림 팝업 (2026-09-11)

- 계기: 이전 검토에서 `test_gui_flow.py`가 간헐적으로 실패하는 것을 발견 → 원인은 테스트의 고정
  딜레이가 아니라 **앱 자체의 구조적 경합**이었음: `_refresh_list()`가 presence 이벤트를 받을 때마다
  사이드바 행(row) 위젯을 전부 destroy 후 재생성했는데, 사용자의 클릭이 아직 처리되기 전인 같은 GUI
  틱에 이 재생성이 끼어들면 클릭 대상 위젯이 사라져 클릭이 조용히 유실됨. 이어서 사용자가 (1) 상용
  메신저 수준 재설계 (2) 단체대화방 (3) 알림 팝업을 요청 → 한 번에 정리.
- **플레이키 테스트 근본 수정**: `_refresh_list()`를 "전체 destroy 후 재생성"에서 `self._rows` 딕셔너리
  기반 **키 diff 갱신**으로 교체(없어진 키만 destroy, 있는 키는 라벨/미리보기/뱃지만 config, 새 키만
  생성 — 순서는 pack_forget 후 재pack으로만 처리, 위젯 자체는 파괴하지 않음). `test_gui_flow.py`도
  고정 `root.after(ms)` 방식을 폐기하고 `wait_gui(cond, timeout)` 조건 폴링 방식으로 재작성 — 5회 연속
  실행으로 재발 없음 확인.
- **텔레그램풍 재설계**: 색상 체계를 블루 포인트(`#3390ec`)로 교체. 채팅 렌더링을 `tk.Text` 태그 기반
  사각 배경에서 **`tk.Canvas` 기반 완전 재작성**으로 교체 — 메시지마다 `create_text`로 먼저 텍스트를
  그리고 `bbox()`로 실제 렌더 크기를 측정한 뒤 그 크기에 맞춰 `round_rect()`(스무딩 폴리곤)로 진짜 둥근
  말풍선을 뒤에 깔아 `tag_lower`. 텍스트 자동 줄바꿈은 Tk의 `create_text(width=...)` 내장 기능을 그대로
  활용해 직접 word-wrap 알고리즘을 구현하지 않음(리스크 축소). 스크롤은 Canvas의 `yview_moveto(1.0)`로
  단순화되어 기존 Text의 "top-anchor라 빈 줄 패드 필요" 편법이 사라짐.
  - **트레이드오프**: Canvas 텍스트는 Text 위젯과 달리 마우스 드래그로 부분 선택·복사가 안 됨 →
    보완으로 말풍선 클릭 시 해당 메시지 전체를 클립보드로 복사하는 기능을 추가.
- **단체대화방**: 서버가 없으므로 각 클라이언트가 아는 멤버에게 개별 유니캐스트로 팬아웃하는 방식.
  신규 패킷 `group_invite`(로스터 전파, ack+재시도)·`group_msg`(메시지 팬아웃, 현재 로스터 스냅샷 동봉).
  수신측은 로스터를 **합집합(union)** 으로만 갱신 — 초대를 놓친 멤버도 다른 멤버의 메시지를 통해
  점진적으로 합류하는 가십 전파 구조. 그룹 생성/멤버 추가 시 최근 대화 50건을 함께 보내 신규 합류자의
  맥락 단절을 완화. 자기 자신이 자기 그룹의 멤버 목록에 남지 않도록 `_is_self()` 필터 추가(포트 일치 +
  실제 로컬 IP 또는 127.0.0.1 — 후자는 같은 머신에서 포트만 바꿔 여러 엔진을 띄우는 루프백 테스트
  환경을 위한 것으로, 실제 배포 환경에서는 상대가 127.0.0.1일 수 없으므로 오탐 없음).
  - **한계(문서화 완료, README 참고)**: 오프라인 중 수신 못 한 메시지의 캐치업 없음(1:1과 동일 제약),
    멤버 삭제·탈퇴 미지원.
- **알림 팝업**: 외부 패키지 없이 `ctypes`로 `Shell_NotifyIconW`(트레이 풍선)를 직접 호출하는 `Notifier`
  클래스 추가. 창이 포커스 없거나 다른 대화를 보고 있을 때만 트리거, `FlashWindow`로 작업표시줄 깜빡임도
  병행. 모든 호출을 광범위한 try/except로 감싸 실패해도 앱이 죽지 않게 함(이 사내 PC들에 EDR 계열
  보안 프로그램이 상주한다는 것이 이미 6절에 문서화되어 있어 방어적으로 설계).
  - 실측: 이 개발 환경에서 `Shell_NotifyIconW` 호출 자체는 예외 없이 성공(`Notifier.ok == True`)까지
    확인. 다만 OS 토스트가 실제로 사용자 화면에 표시되는지는 자동화 환경에서 캡처할 수 없어 **사용자
    실행 화면에서 최종 확인 필요**(5절의 기존 원칙과 동일).
- 검증: `test_headless.py`(1:1 케이스 전부 + 신규 그룹 프로토콜 3~4자 시뮬레이션), `test_gui_flow.py`
  (1:1 + 그룹 생성·팬아웃·가십 전파까지 조건 폴링으로 검증, 5회 연속 통과), `smoke_gui.py` 전부 통과.
  Pillow를 임시 검증 스크립트에서만 사용해(배포 코드에는 포함 안 됨) 실제 창을 스크린샷으로 캡처해
  둥근 말풍선·그룹 아이콘·미리보기 텍스트 갱신을 육안으로도 확인.
