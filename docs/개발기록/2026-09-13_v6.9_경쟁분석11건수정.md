# v6.9 경쟁 프로그램 비교 분석 보고서 11건 코드 대조 검증 후 전부 수정 (2026-09-13)

- **계기**: 경쟁 오픈소스 프로그램(lanmessenger.github.io)과 비교해 개선할 점을 검토해달라는
  이전 요청과는 별개로, 이번엔 이미 작성된 "코드 재검토 및 버그 분석 보고서"(11건, High 4·
  Medium 3·Low/UX 4)를 받아 검토해달라는 요청. 다른 세션/도구가 만든 분석을 그대로 믿고
  고치지 않고, 보고서가 지목한 파일:줄번호를 실제 코드와 하나하나 대조해 진짜인지부터
  확인한 뒤 착수했다(이 프로젝트에서 반복적으로 강조된 원칙 — 추측이 아니라 실측으로
  검증).
- **검증 방법**: `Grep`/`Read`로 보고서가 지목한 정확한 라인을 직접 읽어 대조. 11건 전부
  보고서 설명과 실제 코드가 일치함을 확인(허위·과장 없음). 수정 후에는 기존 회귀 스위트
  3종(`test_headless.py`/`smoke_gui.py`/`test_gui_flow.py`) 전체 재실행 + 각 항목을 직접
  겨냥한 별도 검증 스크립트(엔진을 실제로 띄워 파일을 쓰고 읽고, 실제 tkinter 위젯을 만들어
  실제 메서드를 호출)를 새로 작성해 실행했다.

- **[High] #1 공지창(`_broadcast_dialog`) 안 Ctrl+V가 메인 대화방으로 새는 버그**
  (`app.py:_on_window_paste`): 루트에 걸린 `<Control-v>` 핸들러가 포커스 위젯이
  `(tk.Entry, ttk.Entry)`인지만 검사하고 `tk.Text`는 걸러내지 않아서, 공지창의 메시지
  입력칸(tk.Text)에 포커스가 있어도 그대로 통과해 현재 열려 있던 대화방으로 붙여넣기가
  전송됐다. **수정**: 포커스 위젯의 `winfo_toplevel()`이 루트 창이 아니면(=다른
  대화상자 안이면) 아예 처리를 스킵하도록 최우선 검사를 추가하고, 보조로 `tk.Text`도
  제외 대상에 포함시켰다. **검증**: 실제 `App`을 만들고 `focus_get()`만 진짜 위젯으로
  바꿔치기해(실제 OS 포커스/grab을 거치면 이 프로젝트에서 과거에도 여러 번 멈춤이
  있었던 이력이 있어 그 경로는 피함) 4가지 케이스(공지창 Text/메인 입력창/채팅 캔버스/
  포커스 없음)를 실제로 호출해 확인 — 채팅 캔버스(`self.chat`)는 원래도 자체
  `<Control-v>` 바인딩으로 붙여넣기를 받는 게 의도된 동작이라 그대로 유지됨을 재확인.

- **[High] #2 통합 검색(`search_all_logs`)이 최신 대화를 누락하는 버그** (`engine.py`):
  `os.listdir()` 순서대로 파일을 훑다가 `limit`이 차는 즉시 `return`해버려서, 최근 대화
  파일이 뒤쪽에 걸리면 정작 최신 메시지는 검색 결과에서 통째로 빠지고 오래된 메시지만
  나왔다. **수정**: 파일을 `mtime` 내림차순(최근 대화방 우선)으로 정렬해서 순회하고,
  도중에 끊지 않고 전부 모은 뒤 마지막에 `ts` 기준 정렬 후 `[:limit]`로 자르도록 변경.
  **검증**: 오래된 메시지 40건(mtime을 실제로 과거로 조작)과 방금 나눈 메시지 1건을
  같은 검색어로 만들어두고, 최신 메시지가 결과에 포함되는지 실제로 확인.

- **[High] #3 실시간 렌더 시 말풍선 사이 여백이 계속 누적되는 버그** (`app.py:_finish_render`):
  `self._chat_y += PAD_BOTTOM`이 "다음 말풍선을 그릴 좌표"를 담는 상태 변수 자체를 영구히
  밀어버렸다. `_reload_chat`은 전체를 그린 뒤 1회만 호출해서 티가 안 났지만, 실시간
  송수신 경로(`_append_bubble`)는 메시지마다 이 함수를 호출해서 매번 여백이 누적됐다 —
  다른 방을 다녀오면(`_reload_chat` 재호출) `_chat_y`가 리셋되며 갑자기 좁아지는 것도
  같은 원인. **수정**: `scrollregion` 계산에만 국소적으로 `PAD_BOTTOM`을 더하고,
  `self._chat_y` 자체는 건드리지 않도록 분리. **검증**: 실제 `App` 인스턴스에서 메시지
  5개를 실시간 경로로 연속 추가한 뒤의 `_chat_y`와, 같은 5개 레코드를 `_reload_chat`으로
  완전히 새로 그렸을 때의 `_chat_y`가 정확히 일치하는지 확인(수정 전에는 달랐을 값).

- **[High] #4 저장 도중 강제 종료 시 대화기록·설정 파일이 통째로 손상될 위험**
  (`engine.py`): `_update_settings`/`_mark_read_in_log`/`_mark_group_read_in_log`/
  `_save_groups`가 전부 `open(path, "w")`로 기존 파일을 바로 truncate 후 썼다.
  `crypto_layer.py`의 키 생성 로직은 이미 임시파일+`os.replace` 원자적 쓰기를 쓰고
  있었는데 대화 로그 계층에는 빠져 있었다. **수정**: `Engine._atomic_write_text()`
  헬퍼를 새로 만들어(`.tmp{pid}`에 먼저 쓰고 `os.replace`) 네 곳 전부 통일. **검증**:
  실제로 파일을 쓴 뒤 데이터 디렉터리에 `.tmp` 잔여 파일이 남지 않는지 확인.

- **[Medium] #5 읽음 확인(`read_ack`)마다 로그 전체를 재작성하던 I/O 병목**
  (`engine.py:_mark_read_in_log`, `_mark_group_read_in_log`): 안 읽은 메시지가 N개인
  방을 열면 `read_ack`가 N번 연달아 와서, 그때마다 대화 전체를 읽고 다시 썼다. **수정**:
  `threading.Timer`로 300ms 동안 도착한 mid들을 `_read_ack_pending`/`_gread_ack_pending`에
  모았다가 한 번만 실제 파일을 읽고-쓰기(atomic write와 결합)하도록 배치 처리로 변경.
  기존 "mid 미지정 = 전체 읽음" 의미는 `None`을 섞어 그대로 보존. **검증**: mid 5개를
  연속으로 `_mark_read_in_log()` 호출한 직후엔 아직 pending 상태이고, 300ms 뒤엔 전부
  반영되고 pending이 정리되는지 실제 파일로 확인.

- **[Medium] #6 검색어 입력 시 GUI 스레드가 디스크 I/O로 멈추던 문제**
  (`app.py:_refresh_list`): `eng.search_all_logs()`를 메인 GUI 스레드가 직접 호출해서,
  로그가 많이 쌓인 상태에서 타이핑할 때마다 창이 잠깐씩 멈췄다. **수정**:
  `_start_async_log_search()`가 검색을 백그라운드 스레드로 넘기고, 결과는
  `root.after(0, ...)`로 GUI 스레드에 안전하게 되돌린다. 검색어가 바뀌는 사이 도착하는
  낡은 결과는 세대 번호(`_search_gen`)로 걸러 버린다.

- **[Medium] #7 그룹 파일 전송 순차 병목 및 `_resume_info` 경쟁 상태** (`engine.py`):
  그룹에 파일을 보낼 때 멤버 1명씩 처음부터 끝까지 다 보낸 뒤 다음 멤버로 넘어갔다(5명
  그룹·20MB 파일이면 사실상 80MB를 순차 전송). 또한 이어받기 위치(`resume_from`)를
  담는 `_resume_info`의 키가 `fid` 하나뿐이라, 멤버들이 거의 동시에 `file_offer_ack`를
  보내면 서로의 값이 덮어써질 위험이 있었다. **수정**: 키를 `(fid, ip, port)`로 바꿔
  피어별로 분리하고, 멤버별 전송 로직을 `_file_send_to_member()`로 분리한 뒤 그룹
  전송 시 멤버마다 스레드를 띄워 병렬로 전송하도록 변경(1:1 전송은 기존과 동일하게
  순차). 진행률(`file_progress`) 이벤트는 상태표시줄 텍스트 용도라 여러 멤버가 동시에
  진행돼도 기능상 문제는 없음을 확인. **검증**: 서로 다른 두 피어에 대해 같은 `fid`로
  `_resume_info`를 동시에 채워두고 `_wait_resume_from()`이 서로 섞이지 않고 각자 정확한
  값을 돌려주는지 확인 + 기존 회귀 스위트의 "그룹 파일 팬아웃" 테스트 통과 재확인.

- **[Low/UX] #8 검색 결과로 이동해도 어떤 말풍선인지 강조 표시가 없던 문제**
  (`app.py`): `constants.py`에 정의만 되고 한 번도 쓰이지 않던 `C_SEARCH_HL` 색상을
  실제로 사용해, `_scroll_to_match()`가 스크롤 이동 후 해당 말풍선 영역에 반투명
  사각형을 잠깐(1.4초) 그렸다가 지우도록 `_flash_highlight()`를 추가. 각 레코드의
  시작/끝 y좌표를 `_record_y_positions`/`_record_y_end`로 함께 추적하도록 확장.

- **[Low/UX] #9 그룹 멤버 목록 갱신 시 마우스 휠이 풀리던 버그** (`app.py`):
  `win.bind("<Destroy>", ...)`가 창 자체가 아니라 `reload_members()`가 내부 위젯을
  갱신할 때 파괴되는 자식 위젯의 `<Destroy>`에도 반응해(Tk에서 자식의 Destroy가
  부모로 버블링됨) 휠 바인딩이 조기 해제됐다. **수정**: `if e.widget == win:` 조건을
  추가해 창 자체가 닫힐 때만 언바인드.

- **[Low/UX] #10 다른 프로그램으로 전환해도 우클릭 팝업 메뉴가 화면에 남던 문제**
  (`app.py:_popup_menu`): 바깥 클릭 감지만 있고 "앱 자체가 포커스를 잃는" 경우는
  다루지 않았다. **수정**: `root.bind("<FocusOut>", ...)`을 추가하고, 팝업 자신에게
  포커스가 옮겨가서 발생하는 거짓 트리거와 구분하기 위해 한 틱 뒤 `focus_get()`이
  `None`인지 다시 확인하는 방식으로 실제로 앱 밖으로 나갔을 때만 닫히게 했다. **검증
  참고**: 이 항목은 실제 Windows 포커스/topmost 창 API를 거치는 자동화 테스트가 이
  세션 환경(대화형 데스크톱 세션이 아닌 자동화 실행 컨텍스트)에서 재현 없이 멈춰버려
  (과거 `_prompt_text`/위젯 클릭 시뮬레이션 검증 때도 동일한 종류의 멈춤이 있었던
  전례와 같은 범주) 라이브 재현 검증은 하지 못했고, 코드 리뷰 + 컴파일 + 기존 회귀
  스위트 무영향 확인으로 갈음했다.

- **[Low/UX] #11 멘션(@) 팝업 빈 공간 클릭 시 1번 멤버가 강제로 자동완성되던 버그**
  (`widgets.py:MentionPopup.get_selected`): 실제 선택이 없을 때 `self._items[0]`으로
  대체하던 방어 코드가 있어서, 취소하려고 빈 곳을 눌러도 첫 번째 멤버가 삽입됐다.
  **수정**: 선택이 없으면 `None`을 반환하도록 단순화. **검증**: 실제 `MentionPopup`을
  만들어 `listbox.selection_clear()`로 선택 없는 상태를 만든 뒤 `get_selected()`가
  `None`을 반환하는지 확인.
