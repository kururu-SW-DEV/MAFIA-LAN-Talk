# v6.25 — 표준 이모지 제거, 스티커 전용 패널로 전환 (2026-09-13)

## 계기

v6.24에서 이모지 피커의 초기 기동 지연 원인(Windows가 "Segoe UI Emoji" 글꼴로
문자를 처음 그릴 때 치르는 1회성 비용)을 실측·설명한 뒤, 사용자가 "이모지를 전부
스티커로 바꾸면 속도가 빨라지니?"라고 물었다. 스티커는 이 글꼴을 아예 쓰지 않는다
(원·곡선·다각형 도형 + 평범한 "맑은 고딕" 캡션)는 사실과, 그럼에도 표준 이모지라는
기능 자체를 잃는다는 트레이드오프를 안내한 뒤, 사용자가 "전부 스티커로 바꿔줘"로
확정했다.

작업 도중 사용자가 "재미나이(Gemini)를 통해 코드를 많이 고쳤다"고 알려왔다 —
실제로 `app.py`를 다시 읽어보니 세션 도중에 파일이 바뀌어 있었다. Gemini 쪽에서
이미 이모지 피커 생성을 **지연 초기화**(`_get_emoji_picker()`가 최초 클릭 시에만
`EmojiPicker`를 만듦)로 바꿔 두었고, v6.24의 "청크 단위 프리웜" 코드는 빈
`_prewarm_emoji_fonts()` 스텁으로 대체돼 있었다 — 방향은 다르지만 같은 문제(창이
뜨기 전에 무거운 렌더를 미리 치르는 것)를 겨냥한 개선이었다. 이번 작업은 그 위에서
진행했다.

## 변경 내용

- **`widgets.py`**: `EMOJI_CATEGORIES`(스마일리·제스처·하트·동물·음식·활동/사물,
  총 200개 이상의 유니코드 이모지)와 `_TAB_ICONS` 전부 제거. `EmojiPicker`를
  "최근"/"스티커" 2탭짜리 스티커 전용 패널로 재작성 — `_render_emoji_grid`,
  `_emoji_map`, `_emoji_pitch`, `_on_emoji_item_click/enter/leave`, `_cur_kind`
  분기(이제 스티커 하나뿐이라 필요 없음)를 전부 걷어냈다. 탭 라벨도 아이콘
  한 글자(`_TAB_ICONS`, `("Segoe UI Emoji", 13)` 사용)에서 **평범한 한글
  텍스트**("최근"/"스티커", 일반 폰트)로 되돌렸다 — 탭이 2개뿐이라 좁은 채팅
  영역에서도 겹칠 걱정이 없고, 결정적으로 이 패널 어디에도 더 이상 "Segoe UI
  Emoji" 글꼴을 요청하는 코드가 없다.
- **"최근" 탭 = 최근 사용 스티커**: 기존엔 "최근 사용 이모지"였는데, 이모지 자체가
  없어졌으니 스티커 기준으로 바꿨다. `engine.py`의 `get_recent_emoji`/
  `add_recent_emoji`(설정 키 `recent_emoji`)를 `get_recent_stickers`/
  `add_recent_sticker`(설정 키 `recent_stickers`)로 교체 — 패턴은 동일(항상
  앞으로 재정렬, 최대 24개), `add_recent_sticker`만 유효한 스티커 id인지
  `stickers.STICKERS`로 한 번 더 검증한다. `app.py`의 `_send_sticker()`가
  실제로 전송할 때마다 `add_recent_sticker(sticker_id)`를 호출하도록 연결했다.
- **`app.py`**: `_on_emoji_select`(이모지 문자를 입력창에 삽입하던 콜백)와 이제는
  아무 일도 안 하던 `_prewarm_emoji_fonts` 스텁을 제거. `EmojiPicker(...)` 생성
  호출에서 `on_select=` 인자를 뺐다(이제 존재하지 않는 콜백). 입력 바의 이모지
  버튼(`emoji_btn`, `PillButton`의 "😊" 텍스트)은 그대로 뒀다 — `PillButton`이
  이미 "😊"/"⏱" 두 문자를 특수 처리해 실제 이모지 글리프 대신 벡터 도형(동그라미+
  눈+웃는 선)으로 직접 그리고 있어서(Gemini 또는 그 이전 작업에서 추가된 방어
  코드로 추정) 이 버튼 자체는 애초에 느려지는 원인이 아니었다 — 문자만 다른
  아이콘으로 바꿨다면 오히려 특수 처리 목록에 없어 실제 이모지 글꼴로 폴백하는
  회귀가 생겼을 것.

## 검증

- 실제 `App`을 화면에 띄우고 대화를 연 뒤 이모지 버튼을 처음 눌러 걸리는 시간을
  직접 측정: 761.5ms(스티커 28개 캔버스를 새로 그리는 비용 — 도형이라 글꼴
  예열이 필요 없고, 이 수치는 이 검증 환경의 Tcl 호출 오버헤드가 반영된 것이라
  실제 PC에서는 더 빠를 가능성이 높다). 탭 목록이 `['최근', '스티커']`로 정확히
  2개인 것 확인.
- 스티커를 실제 클릭(진짜 클릭 경로, `_pick_sticker` 경유)해 전송 → 패널이
  자동으로 닫히는지, 다시 열어 "최근" 탭을 클릭하면 방금 보낸 스티커가 정확히
  1개 나타나는지 스크린샷으로 확인.
- 기존 회귀 스위트 3종(`tests/test_headless.py`, `tests/smoke_gui.py`,
  `tests/test_gui_flow.py`) 각 1~2회 재실행, 전부 통과.
- `recent_emoji`/`recent_stickers`/`EMOJI_CATEGORIES`/`_TAB_ICONS` 이름으로 전체
  코드베이스를 다시 grep해 죽은 참조가 하나도 안 남았는지 확인.

## 의도적으로 하지 않은 것

- 입력 바의 이모지 버튼 아이콘(😊)을 스티커를 상징하는 다른 문자(예: 🎨)로 바꾸는
  것은 하지 않았다 — 위에서 설명한 대로 `PillButton`의 벡터 폴백 특수 처리
  목록에 없는 문자로 바꾸면 오히려 실제 이모지 글꼴 렌더링이 되살아나(그 문자
  하나에 대해서만이지만) 이번 작업의 취지와 어긋난다. 아이콘을 꼭 바꾸고
  싶다면 `PillButton`에 그 문자에 대한 벡터 그리기 분기를 새로 추가하는 방식이
  안전하다.
- `settings.json`에 남아있을 수 있는 예전 `recent_emoji` 키는 그대로 뒀다(읽지도
  쓰지도 않으므로 무해한 죽은 데이터) — 마이그레이션이나 삭제는 하지 않았다.
