# v6.15 — 대화방 공지사항 고정(카카오톡 스타일) + 공지창 자동 폭파 옵션 (2026-09-13)

- **계기**: 상용 메신저 비교 분석에서 나온 "⑦ 중요 메시지 공지 상단 고정" 항목을 사용자가
  직접 요청("채팅창 안에 특정 메시지를 개별 대화목록의 공지사항으로 지정할 수 있게 해줘.
  카카오톡 같이"). 이어서 공지창(`_broadcast_dialog`)에도 자동 폭파 타이머가 적용되는지
  질문을 받아, 안 되는 걸 확인하고 그 자리에서 추가 요청을 받아 함께 구현했다.

## 공지사항 고정

- **동기화 여부 결정**: 카카오톡의 단체방 공지는 누가 지정해도 전원이 같은 걸 본다.
  이 앱은 1:1이든 그룹이든 서버가 없는 대등한(symmetric) 구조라, "내 화면에만 보이는
  개인 북마크"가 아니라 **상대(들)에게도 네트워크로 전파되는 진짜 공지**로 만들었다 —
  그래야 "공지"라는 단어의 의미에 맞는다.
- **데이터 모델 (`engine.py`)**: `Engine.pinned_notices` — `"dm:ip:port"`/`"grp:gid"` ->
  `{"mid","text","sender","ts"}`. 이미 있던 `contact_categories`(친구 카테고리)와 완전히
  같은 저장 패턴(`_load_pinned_notices`/`_save_pinned_notices`, `settings.json`에 영속화)을
  재사용했고, 키 변환도 이미 있던 `_key_to_str`/`_str_to_key` 헬퍼를 그대로 썼다(새로 만들지
  않음).
- **네트워크 (`engine.py`)**: 신규 패킷 `pin_notice`/`unpin_notice`. 1:1은 상대에게 1번,
  그룹은 `send_group_message`와 같은 멤버별 유니캐스트 팬아웃 방식으로 전원에게 보낸다.
  실패 시 다른 그룹 브로드캐스트(예: `group_leave`)와 동일하게 `_enqueue_outbox`로
  재시도 큐에 들어간다. 수신 측은 `set_pinned_notice(..., _from_network=True)`로 반영하고
  다시 브로드캐스트하지 않는다(무한 루프 방지).
- **UI (`widgets.py`, `app.py`, `chat_renderer.py`)**:
  - `widgets.PinBanner` — `ReplyBanner`와 같은 스타일의 새 위젯. 대화 헤더 바로 아래,
    채팅 캔버스 바로 위에 배치(공지 없을 때는 `pack_forget`으로 완전히 숨김).
  - 말풍선 우클릭 메뉴(`_draw_bubble`의 `_context_menu`)에 `[📌 공지로 등록]`/
    `[📌 공지 해제]`를 추가. 이미 있던 mid를 그대로 재사용하려고 `_draw_bubble`/
    `_draw_record`에 `mid`, `ts` 매개변수를 추가로 흘려보내도록 확장.
  - 배너 클릭 시: 저장된 `mid`로 현재 로드된 `self._active_chat_records`를 순회해 인덱스를
    찾고 기존 검색 기능의 `_scroll_to_match()`(하이라이트까지 재사용)로 이동. 원본이
    지워졌으면(자동 폭파·기록 삭제 등) 예외 없이 "찾을 수 없음" 안내만 뜨도록 방어.
  - `"pinned"` 이벤트를 새로 만들어 `_pump()`에서 처리 — 내가 지정했든 상대(그룹원)가
    지정했든 같은 경로로 배너가 갱신된다. `"burned"`/`"history_deleted"` 이벤트 처리부에도
    배너 갱신을 끼워 넣어, 공지로 걸린 메시지가 사라지는 상황에도 화면이 안 어긋나게 했다.
  - 대화방을 벗어나거나(그룹 나가기·대화 기록 삭제·대화 숨기기) 목록이 빈 상태로 돌아가는
    기존 4곳의 "UI 초기화" 코드에 배너 숨김도 추가.

## 공지창(브로드캐스트) 자동 폭파 옵션

- `_broadcast_dialog`(`dialogs.py`)에 메시지 입력창 아래로 `⏱ 자동 삭제` 라벨을 추가.
  클릭하면 메인 화면의 `⏱` 버튼과 같은 `_BURN_OPTIONS`/`_popup_menu`를 재사용한 팝업이
  뜨고, 고른 값은 이 공지 전송 1회에만 적용되는 로컬 변수(`burn_state`)로 관리한다(대화방별
  로 유지되는 `self._burn_mode`와는 별개 — 공지는 매번 다른 사람들에게 새로 보내는 것이라
  "꺼질 때까지 유지"가 의미가 없다).
- 전송 시 각 수신자에게 개별 1:1 메시지로 나가므로, 여기서 고른 `burn_sec`은 그대로
  `engine.send_message(..., burn_sec=burn_sec)`에 실려 이미 있던 1:1 자동 폭파 로직
  (상대가 읽은 시점부터 카운트다운)을 그대로 탄다 — 엔진 쪽은 전혀 손대지 않았다.

## 검증

- **엔진(네트워크) 검증**: 실제 Engine 인스턴스로 (1) 1:1에서 A가 지정 → B에게 네트워크로
  전파되어 동일한 공지가 반영, `settings.json`에도 영속화, (2) A가 해제 → B에게도 해제
  전파, (3) 3자 그룹(A/B/C)에서 A가 지정 → B·C 전원에게 전파 — 총 8개 항목 확인.
- **GUI 상태 검증**: 실제 `App` 인스턴스로 공지 등록 전/후 배너의 `winfo_manager()`
  ("pack"인지 아닌지로 실제 표시 여부 판정 — `winfo_ismapped()`는 테스트 환경에서 root가
  `withdraw()`돼 있어 항상 거짓을 반환하는 함정이 있어 처음엔 잘못된 통과를 얻었다가
  재검토로 고쳤다), 배너 텍스트에 발신자·내용이 정확히 반영되는지, 배너 클릭 시 저장된
  mid에 해당하는 정확한 레코드 인덱스로 스크롤을 시도하는지, 해제 후 배너가 다시 숨겨지고
  엔진 상태도 지워지는지, 원본이 없는 "유령" mid를 가리키는 공지를 클릭해도 예외 없이
  안전하게 처리되는지까지 8개 항목 확인.
- 이번에도 실제 `Toplevel` 다이얼로그(공지창)를 열고 `root.update()`를 호출하는 경로는
  이 자동화 세션에서 재현 없이 멈추는 환경 한계(이미 여러 차례 문서화된 것과 같은 범주)에
  다시 부딪혔다 — 공지창의 자동 폭파 옵션 자체는 배너 기능과 무관하게 이미 검증해둔
  `_send()`의 `burn_sec` 전달 패턴을 그대로 재사용한 것이라 코드 리뷰로 갈음했다.
- 기존 회귀 스위트 3종(`test_headless.py`/`smoke_gui.py`/`test_gui_flow.py`) 재실행,
  전부 통과.
