# v6.25 — 초기 기동 속도 완전 최적화 (2026-09-13)

## 1. 개요 및 계기

v6.22 대비 v6.24에서 앱 초기 기동 및 창이 뜬 직후 마우스 조작이 뚝뚝 끊기는 현상이 발생함.
정밀 프로파일러 측정 결과, 두 가지 핵심 병목이 규명됨:
1. **창이 뜨기 전 지연 (약 1.6~1.7초 소모)**:
   - 검색창 돋보기(🔍), 입력 바 버튼(😊, ⏱), 공지 배너(📌), 이모지 피커(EmojiPicker) 탭 라벨(🕒, 🎨, 😀, 👍, 🐶, 🍔)이 렌더링되면서 Windows 시스템 글꼴 폴백(Segoe UI Emoji 로드 및 매핑)이 발생해 첫 글리프에서만 **약 980ms**, 이후 탭 라벨 생성에서 **약 280ms** 소모.
2. **창이 뜬 직후 UI 프리징 (약 2.3초간 22회 멈춤)**:
   - v6.22에서는 _prewarm_emoji_fonts가 스티커 탭 처리 도중 예외(TclError)로 인해 1ms 만에 조용히 중단되어 백그라운드 프리징이 없었음.
   - v6.24에서 이를 수정하면서 257개 이모지를 86개 배치로 나누어 메인 스레드에서 렌더링하도록 변경됨. 이로 인해 100~140ms 길이의 메인 스레드 블로킹이 22회 연속 발생(총 2,312ms 프리징).

---

## 2. 해결 및 구현 내용

### ① 백그라운드 이모지 전수 예열(_prewarm_emoji_fonts) 완전 제거
- 메신저 시작 시 사용자가 열지도 않은 257개 이모지를 메인 스레드에서 강제 렌더링하던 루프를 완전히 제거함.
- _prewarm_emoji_fonts()는 no-op으로 전환하여 창이 뜬 직후의 **2.3초간 22회 UI 화면 멈춤을 0ms(완전 제거)**로 개선.

### ② 이모지 피커 지연 생성 (Lazy Loading)
- _build_shell() 실행 시 EmojiPicker 인스턴스를 미리 생성하지 않고, 사용자가 입력 바의 이모지 버튼(😊)을 처음 클릭할 때(_get_emoji_picker()) 생성하도록 변경.
- 앱 기동 시 8개 탭 버튼 및 내부 위젯 생성 비용(~280ms)을 기동 경로에서 제외.

### ③ 검색창 및 버튼 아이콘 경량 벡터 드로잉 전환
- **검색창 돋보기 아이콘**: 	k.Label(text=🔍) 대신 경량 Canvas 기반 make_search_icon 도입 (0.05ms, 글꼴 폴백 방지).
- **입력 바 버튼 (PillButton)**: 😊, ⏱ 텍스트 렌더링 시 Segoe UI Emoji 폰트 로드로 1초간 멈추던 문제를 방지하기 위해 Canvas 내장 벡터 아이콘으로 렌더링.
- **공지사항 배너 (PinBanner)**: 초기화 시점에는 아이콘을 빈 텍스트로 두고, 실제 공지가 표시되는 set_notice() 호출 시점에 핀 아이콘을 설정하도록 지연.
