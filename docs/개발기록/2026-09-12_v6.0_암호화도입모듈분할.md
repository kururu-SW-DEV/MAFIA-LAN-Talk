# v6.0 통신 암호화(HMAC) 도입, 코드 9개 모듈 분할, 프로필 사진, JPG 제로설치 미리보기, 아바타/버튼 진짜 알파 투명 렌더링 개편 (2026-09-12)

- **평문 스니핑/스푸핑 방지 — HMAC 기반 경량 암호화 계층 신설 (`crypto_layer.py`)**:
  - 문제: "사내비밀메신저"라는 이름과 달리 모든 패킷이 UDP로 평문 JSON 전송되어, 같은 네트워크의
    누구나 스니핑으로 대화 내용을 그대로 읽거나 패킷을 위조해 스푸핑할 수 있던 상태.
  - AES 등 대칭암호가 표준 라이브러리에 없어(외부 패키지 설치 없이 폐쇄망에서 100% 동작해야
    한다는 프로젝트 원칙), `hmac.new(key, counter, sha256)`를 카운터 모드 PRF로 써서 키스트림을
    생성하는 스트림 암호(XOR)와, 별도 HMAC-SHA256 태그로 전문을 인증하는 **Encrypt-then-MAC** 구조를
    직접 구현. `load_or_create_key()`가 각 설치 폴더에 `secret.key`를 자동 생성·공유.
  - `Engine._send_dict`/`_handle`에 암/복호화를 투명하게 끼워 넣어, 위·변조되거나 다른 키로 만들어진
    패킷은 태그 불일치로 조용히 폐기되도록 함(스푸핑 방지).
- **조용히 삼켜지던 예외 → 파일 기반 디버그 로그 (`applog.py`)**:
  - 문제: 네트워크/파일 입출력 실패가 대부분 `except: pass`로 조용히 사라져, 사용자 보고만으로는
    원인 추적이 거의 불가능했음.
  - 꼬리 보존 로테이션이 적용된 파일 로그(`applog.log(...)`)를 신설해 네트워크 오류·파일 처리 실패
    등 주요 지점에 배치.
- **4000줄 이상 단일 파일 → 유지보수용 9개 모듈 분할**:
  - 계기: "불필요한 토큰 소모가 많다"는 피드백 — 매번 거대한 단일 파일 전체를 다시 읽어야 하는
    비효율을 근본적으로 해소하기 위해 책임별로 파일을 분리.
  - `constants.py`(색상/폰트/레이아웃/포트) · `netutils.py`(시간 포맷, 로컬 IP 캐시, 순수 아바타
    이미지 처리, 텍스트 살균) · `canvas_utils.py`(둥근 사각형·원형 아바타 캔버스 렌더 헬퍼) ·
    `crypto_layer.py`(암호화) · `applog.py`(로그) · `winapi.py`(트레이 알림·다크 타이틀바 등 ctypes) ·
    `engine.py`(네트워크 계층) · `widgets.py`(재사용 위젯) · `app.py`(GUI)로 분리, `lan_messenger.py`는
    얇은 진입점(argparse + main)만 남김.
  - 분할 과정에서 회귀 테스트로 발견한 버그: `Engine._append_log`/`_append_group_log`가 `_handle()`이
    넘기는 `av=av_hash` 키워드 인자를 받지 못해 수신 스레드가 매 메시지마다 예외로 죽던 문제(분할
    이전부터 있던 잠재 버그, 내 변경과는 무관하게 테스트로 포착) — `av=""` 기본 인자 추가로 해결.

- **JPG 인라인 미리보기 — 외부 설치 없는 "제로 인스톨" Pillow 벤더링**:
  - 제약: tkinter 표준 `PhotoImage`는 JPEG를 직접 디코딩하지 못함. 그렇다고 폐쇄망에서 `pip install`
    이 필요한 방식은 이 프로젝트의 "표준 라이브러리만 사용, 설치 없이 폴더만 옮겨도 100% 동작"
    원칙에 위배됨(사용자가 "필로우 굳이 설치해야해? 설치 없이도 코드 폴더만 옮겨도 작동되게 해야지"
    라고 직접 교정).
  - 해결: Pillow 휠에서 실제 `PIL` 패키지 디렉터리를 통째로 추출해 `vendor/pil_cp<버전>/PIL/`에
    내장하고, 실행 시점에 `sys.version_info` 기준으로 맞는 폴더만 `sys.path`에 동적으로 꽂는 방식
    (`ensure_vendored_pil()`)으로 전환 — pip이나 인터넷 연결 전혀 불필요. 다운로드한 휠은 PyPI
    JSON API의 SHA256 해시와 대조해 무결성 검증 후 반영.
  - 이후 "지원 범위를 줄여도 된다"는 사용자 지시에 따라 Python 3.10 → 3.11/3.12/3.13 순으로 벤더
    폴더를 정리, 최종적으로 **Python 3.14 전용**(`vendor/pil_cp314/`) 1개만 유지. 지원되지 않는
    파이썬에서는 JPG가 인라인 미리보기 대신 일반 파일카드로 자동 폴백(PNG/GIF/BMP는 영향 없음).
- **스크롤 버튼 및 아바타 원형 렌더링 완전 개편 — "가짜 투명"에서 "진짜 알파 투명"으로**:
  - 1단계(스크롤 버튼): 우하단 맨 아래로 이동 원형 버튼의 사각 모서리가 투명하지 않다는 스크린샷
    피드백 → `SetWindowRgn`+`CreateEllipticRgn`으로 원형 클리핑 적용. 이어서 "가장자리가 거칠다"는
    후속 피드백을 받아 `UpdateLayeredWindow`+`WS_EX_LAYERED`+`CreateDIBSection`으로 픽셀 단위 실제
    알파 채널을 가진 아이콘을 직접 합성하는 방식으로 재구현(신호거리 기반 analytic anti-aliasing).
  - 2단계(아바타 원): 좌상단 프로필 원과 채팅 목록의 1:1/그룹 이중 원(`create_oval`)도 Windows에서
    경계가 계단식으로 거칠다는 지적 → 1차로 `canvas_utils.smooth_circle_photo()`를 신설해 픽셀
    커버리지를 계산해 배경색과 미리 섞은(blend) PPM 이미지로 교체. 그러나 이 방식은 원 바깥쪽이
    "특정 배경색으로 칠해진 사각형"일 뿐 진짜 투명이 아니어서, 그룹 이중 원처럼 이미지가 다른
    이미지 위에 겹칠 때 사각형 모서리가 실제 배경 대신 고정색으로 덮여 어긋나 보이는 문제가 재발
    ("대화 목록이랑 프로필 원형 주변이 투명이 아니라 겹치면 이상하게 보인다"는 스크린샷 피드백).
  - 최종 해결: `zlib`+`struct` 표준 라이브러리만으로 RGBA PNG를 직접 인코딩하는 `_encode_png_rgba()`를
    추가하고, `smooth_circle_photo()`가 원 바깥은 알파 0(완전 투명), 경계는 커버리지 값을 그대로
    알파로 쓰는 진짜 RGBA PNG를 생성하도록 재작성(`tk.PhotoImage(data=..., format="png")`, Tk 8.6부터
    PNG 알파 채널을 그대로 읽어 캔버스에서 정확히 합성). 배경색 인자가 더 이상 필요 없어져
    `_avatar()`/`_avatar_group()` 호출부도 함께 정리.
