# v6.17 — 오리지널 스티커 28종 + 카카오톡 스타일 자동 추천 (2026-09-13)

- **계기**: "이모지와 이모티콘 기능 넣어줘 카톡같이" 요청에서 시작. 이모지(표준 유니코드)와
  이모티콘(카카오톡/텔레그램에서 구매·다운로드하는 캐릭터 스티커 이미지)은 전혀 다른
  것이고, 후자는 텔레그램 것도 포함해 저작권이 아티스트/제작사에 있어 그대로 가져다
  쓸 수 없다는 점을 먼저 정리해 안내했다("텔레그램에서 쓰이니까 저작권이 없는 거
  아니냐"는 질문에도 같은 논리로 답변). 대안으로 이 프로그램만의 오리지널 도형 스티커를
  제안 → 시안(표정 6+메시지 6, 이후 사용자 요청으로 14+14=28종까지 확장)을 Artifact로
  만들어 승인받은 뒤, "전부 적용 + 카카오톡처럼 연관 단어 자동 추천 기능"까지 동시에
  요청받아 함께 구현했다.
- **왜 이미지 파일을 안 만들고 코드로 직접 그리는가**: 시안은 브라우저에서 SVG로
  만들었지만, 실제 앱(Tkinter)에 적용할 때는 PNG 이미지 파일로 미리 만들어 배포에
  포함시키는 대신 **`stickers.py`가 매번 Canvas 기본 도형(원·곡선·다각형·텍스트)으로
  직접 그리는 방식**을 택했다. 이유: (1) 이 프로젝트의 "표준 라이브러리만 사용, 외부
  자산 없이 폴더 복사만으로 동작" 원칙에 맞고, (2) 이미 아바타에 쓰고 있는
  `canvas_utils.smooth_circle_photo()`(4x4 서브픽셀 슈퍼샘플링으로 매끄러운 원형
  PhotoImage를 만드는 순수 파이썬 PNG 인코더)를 그대로 재사용해 스티커 배경 원을 만들고,
  그 위에 이목구비만 벡터로 얹으면 되기 때문. Do Hyeon(구글 폰트, 시안에서 사용)은
  사용자 PC에 없을 수 있어 실제 앱에서는 이미 전역에서 쓰는 `맑은 고딕 Bold`로 대체했다.
- **28종 구성**: `stickers.py`의 `STICKERS` dict에 id별로 `name`(한글 이름), `bg`(배경색),
  `draw`(그리기 함수), `keywords`(자동 추천용 트리거 단어)를 선언. 표정 14종(활짝 웃음·
  하트뿅·시무룩·화남·졸림·깜짝 놀람·감사한 미소·식은땀·무표정·으쓱·멘붕·감동·궁금·수줍음)
  + 문구 14종(OK·NO·점심콜?·저녁콜?·수고!·파이팅!·감사!·축하!·미안!·굿모닝·굿나잇·퇴근!·
  잠깐!·최고!). 곡선(눈·입)은 `create_line(..., smooth=True)` 3점 스플라인으로, 하트/별은
  유니코드 글리프(♥, ★)로 단순화, 달은 배경색으로 "물어뜯은" 원 두 개 겹치기 트릭으로
  초승달을 표현하는 등 SVG 시안을 Tkinter Canvas 프리미티브로 최대한 충실히 옮겼다.
- **전송/저장 프로토콜 — 기존 메시지 인프라 재사용**: 새 패킷 타입을 만들지 않고,
  기존 `send_message`/`send_group_message`에 `sticker_id` 매개변수를 추가하는 방식을
  택했다. `sticker_id`가 있으면 본문 텍스트를 비워도(`""`) "빈 메시지라 무시" 가드를
  건너뛰도록 하고, 로그 레코드에 `kind="sticker"`+`sticker_id`를 심는다(`kind="file"`을
  이미 같은 방식으로 다루고 있어 자연스러운 확장). 그 결과 **읽음 확인, 자동 폭파 타이머,
  그룹 팬아웃, 오프라인 아웃박스 재시도, 암호화 저장까지 기존 메시지 기능을 전부 코드
  변경 없이 그대로 물려받는다** — 이번에 진짜로 새로 만든 네트워크 로직은 없다.
  초대 스냅샷(`_recent_group_history`)에는 파일과 마찬가지로 스티커도 제외했다(텍스트가
  없어 스냅샷 형식과 안 맞음).
- **렌더링**: 카카오톡처럼 말풍선 배경 없이 스티커 그림만(지름 96px, `STICKER_DIAMETER`)
  뜨도록 `_draw_sticker_item()`을 신설, `_draw_record()`가 `kind` 값에 따라 텍스트/파일/
  스티커 중 하나로 분기하도록 확장. 내가 보낸 스티커를 즉시 내 화면에 그리는
  `_append_sticker()`도 기존 `_append_bubble()`과 같은 구조로 추가.
- **자동 추천 (카카오톡 스타일)**: 입력창의 기존 `<<Modified>>` 살균 파이프라인
  (`_entry_resize`)에 `_check_sticker_suggest()`를 얹어, 타이핑 중인 문구가
  `stickers.match_keywords()`에 걸리면 입력창 바로 위에 추천 스티커(최대 4개)를 작은
  Canvas로 그려 띄운다. 클릭하면 즉시 전송하고 추천 줄만 사라지며, **타이핑 중이던
  글은 그대로 남는다**(카카오톡과 동일 — 초안을 지우지 않음). 키워드는 "네"/"응"/"그래"
  처럼 한국어 문장 어디에나 흔히 등장하는 조사성 단어는 오탐이 너무 잦아 의도적으로
  제외했다(실측 중 "오늘 좀 화나네"가 "화나"와 "네"(OK) 둘 다에 걸리는 오탐을 발견하고
  수정).
- **UI**: 기존 이모지 피커(`EmojiPicker`, v6.16)에 "스티커" 탭을 추가하는 방식으로
  통합했다 — 입력 바에 버튼을 하나 더 추가하지 않은 이유는, 이 프로젝트 개발 초기
  (v4.7)에 버튼이 많아지면 좁은 창에서 잘려 사라지던 버그를 실측으로 잡은 전례가 있어,
  같은 문제를 재발시키지 않으려는 의도적 선택. 스티커 탭은 이모지처럼 텍스트 라벨이
  아니라 각 스티커를 실제로 그린 작은 Canvas(4열 그리드)로 채워지며, 클릭하면 이모지와
  달리 팝업이 자동으로 닫힌다(이모지는 연속 선택을 위해 안 닫히지만, 스티커는 즉시
  전송되는 액션이라 카카오톡처럼 닫는 게 자연스럽다고 판단).
- **검증**: 실제 Engine으로 (1) 1:1 스티커 전송 시 양쪽 로그에 `kind=sticker`로 정확히
  기록되고 빈 텍스트라도 무시되지 않는지, (2) 자동 폭파 타이머(`burn_sec`)가 스티커와
  동시에 정상 적용되는지, (3) 3자 그룹에서 스티커가 멤버 전원에게 팬아웃되는지, (4) 초대
  스냅샷에서 스티커가 올바르게 제외되는지 확인. 실제 `App`으로 (5) `_send_sticker()`가
  정확한 `sticker_id`로 전송하고 내 화면에도 `kind=sticker`로 반영되는지, (6) "점심"
  타이핑 시 추천 줄이 뜨고 매칭 안 되는 문구에서는 사라지는지, (7) 이모지 피커의 새
  "스티커" 탭에 28개 전부가 예외 없이 그려지고 클릭 시 콜백 실행 후 자동으로 닫히는지까지
  총 18개 항목을 직접 실행해 확인. 그리기 함수 28개는 별도로 헤드리스 스모크(예외 없이
  캔버스 아이템 생성, 총 170개 아이템)와 실제 화면에 띄운 렌더 결과까지 확인했다.
  기존 회귀 스위트 3종도 재실행해 전부 통과.
- **의도적으로 범위에서 뺀 것**: 스티커는 텍스트 메시지 확장이라 파일 전송(`send_file`)
  경로는 건드리지 않았고, 캐릭터 그림(진짜 "이모티콘")은 여전히 다루지 않는다 — 필요하면
  나중에 별도 논의.
