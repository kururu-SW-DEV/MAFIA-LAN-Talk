# v6.33 — 트레이 알림 팝업이 전혀 안 뜨던 버그 수정 (2026-09-14)

## 계기

사용자 보고: "근데 지금 프로그램은 알림 팝업이 안뜨네 확인 해줘."

## 원인

`winapi.py`의 `Notifier.__init__()`가 트레이 아이콘 등록에 쓰는 `NOTIFYICONDATA`·
`GUID` ctypes 구조체 클래스가, 별개의 함수 `ensure_dpi_awareness()` **안쪽에
잘못 중첩되어** 정의돼 있었다(아마 v6.28의 고해상도 작업표시줄 아이콘 작업 중
실수로 들여쓰기가 밀린 것으로 추정). 게다가 `ensure_dpi_awareness()`는 보통
`SetProcessDpiAwareness` 성공 시 그 구조체 정의에 도달하기도 전에 `return`해
버려서, 대부분의 경우 이 클래스들은 아예 만들어지지도 않았다.

`Notifier.__init__()`는 모듈 전역에 있는 `NOTIFYICONDATA`를 참조하는데, 위
문제로 실제로는 존재하지 않는 이름이라 `nid = NOTIFYICONDATA()` 줄에서
`NameError`가 발생했다. 그런데 `__init__()` 전체가 "보안 프로그램이 방해할 수
있다"는 이유로 넓은 `try/except Exception: self.ok = False`로 감싸여 있어, 이
`NameError`까지 조용히 삼켜지면서 `notifier.ok`가 항상 `False`로 남았다 — 즉
트레이 아이콘 자체가 한 번도 등록되지 못해 풍선 알림이 뜰 수가 없는 상태였다.

## 수정 (`winapi.py`)

`GUID`·`NOTIFYICONDATA` 클래스 정의를 `ensure_dpi_awareness()` 함수 내부에서
꺼내 `class Notifier:` 바로 위, 모듈 최상위 레벨로 옮겼다(원래 있어야 할
위치로 되돌린 것). 로직 자체는 전혀 바꾸지 않았고 순수하게 스코프(들여쓰기)만
고쳤다.

## 검증

- 실제 `App`을 띄운 뒤 `app._notifier.ok`를 직접 확인 → 수정 전 `False`,
  수정 후 `True`로 바뀜 확인.
- 창의 포커스를 다른 창으로 옮긴 상태에서 `app._notifier.notify(...)`와
  `app._notify_if_needed(...)`를 직접 호출해 예외 없이 끝까지 실행되는 것 확인.
- 기존 회귀 스위트 3종(`test_headless.py`, `test_gui_flow.py`, `smoke_gui.py`)
  재실행, 전부 통과.
- `python -m py_compile`로 전체 모듈 문법 확인.
