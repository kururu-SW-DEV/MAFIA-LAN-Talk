# v6.27 — 창 최소화→복원 시 화면 번쩍임 버그 수정 (2026-09-13)

## 계기

사용자 보고: "창을 최소화 시켰다가 다시 켜면 번쩍 거려."

## 원인

v6.26에서 (재미나이 작업) `winapi.py`의 `apply_dark_titlebar()`에 `win.bind("<Map>", ...)`
가 추가되었다 — 일부 PC에서 타이틀바가 다크 모드 없이 흰색으로 뜨는 문제(창 프레임
HWND가 아직 완성되기 전에 DWM 속성을 적용해 무시당하는 타이밍 문제)를 고치기 위한
의도된 수정이었다.

문제는 `<Map>` 이벤트가 **최초 창 표시뿐 아니라 최소화→복원(iconify→deiconify)마다도
매번 발생**한다는 점이다. 이 바인딩에는 "한 번만 실행" 가드가 없어서, 복원할 때마다
`_apply()`가 다시 불려 최대 3개 HWND(자기 자신·부모·루트) 각각에
`DwmSetWindowAttribute`(다크 모드/캡션 색/텍스트 색 3종) + `SetWindowPos(...,
SWP_FRAMECHANGED)`를 재적용했다. `SWP_FRAMECHANGED`는 창 프레임 전체의 강제
재계산·재도장을 유발하는 플래그라, 복원할 때마다 이미 정상 상태인 타이틀바가 다시
한번 그려지면서 눈에 보이는 번쩍임으로 나타난 것으로 판단했다.

이 가설을 검증하기 위해 `DwmSetWindowAttribute` 호출 횟수를 계측하는 진단 스크립트를
작성해 실제 앱과 동일한 방식으로 `apply_dark_titlebar()`를 호출한 뒤 최소화/복원을
3회 반복 — 최초 기동 직후(초기 1회 적용 + v6.26의 30/100/300/600ms 지연 재적용 4회,
합쳐서 정상적으로 여러 번 불리는 구간)를 제외하면, 이후 3회의 최소화→복원 사이클
동안 호출 횟수가 **정확히 0회 추가**되는지를 확인해 가설을 확정했다(최초 시도에서는
아직 다 소진되지 않은 기동 초기 지연 타이머가 측정 구간에 섞여 들어와 위양성처럼
보였는데, 이벤트 루프를 제대로 펌핑해 그 타이머들을 먼저 다 소진시킨 뒤 재측정하니
깨끗하게 0으로 나왔다).

## 수정

`winapi.py`의 `apply_dark_titlebar()`에서 `<Map>` 핸들러에 1회성 가드를 추가했다.
DWM 창 속성(다크 모드·캡션 색·텍스트 색)은 HWND에 귀속되는 값이라 최소화되어도
사라지지 않으므로, 최초 1회 적용 이후에는 재적용할 필요가 없다.

```python
_mapped_once = [False]

def _on_first_map(e):
    if _mapped_once[0]:
        return
    _mapped_once[0] = True
    win.after_idle(_apply)

win.bind("<Map>", _on_first_map, add="+")
```

v6.26이 고치려던 "기동 시 타이틀바가 흰색으로 뜸" 문제의 수정 경로(최초 `<Map>` 1회
+ 기존 30/100/300/600ms 지연 재적용 4회)는 그대로 유지했다 — 이번 수정은 "두 번째
`<Map>`부터"만 막는다.

## 검증

- 계측 스크립트로 실제 `apply_dark_titlebar()` 호출 경로를 재현해 최소화→복원 3회
  반복 시 `DwmSetWindowAttribute` 추가 호출 0회 확인(수정 전에는 이벤트당 최대
  3~4회씩 재호출됨).

  - `tests/test_headless.py` — `ALL PASSED`

  - `tests/smoke_gui.py` — 3회 연속 `SMOKE PASSED`
- `python -m py_compile`로 `winapi.py` 등 관련 모듈 문법 확인.
