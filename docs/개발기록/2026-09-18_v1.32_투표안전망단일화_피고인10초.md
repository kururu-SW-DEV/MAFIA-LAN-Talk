# v1.32 — 투표창 프리징 잔존 원인 제거 + 피고인 팝업 10초 자동 닫힘 (2026-09-18)

## 사용자 지적
"투표창 프리징은 아직도 여전하고, 내가 처형 대상이 되었을 때 나오는 팝업은
10초뒤 내려지게 해"

## 원인 (실측) — 프리징의 잔존 원인 1건

v1.18/24에 '클릭 피드백+가속 접수'로 화면 반응은 이미 즉시였으나, 개표
타이머가 **이중 예약**되어 있었다:
- 유저 표 접수 → AI 표 다 모이면 8초 안전망 등록(`_update_vote_btn_state` 경로)
- 같은 접수의 else 분기에서도 **15.5초 안전망을 한 번 더 등록**(`_popup_vote`)
→ 두 타이머 경합 → 중복 개표 시도/라인 중복 → '프리징 같은 화면' 체감.

## 조치 (v1.32)

| 항목 | 내용 |
|---|---|
| 안전망 단일화 | `_popup_vote`의 15.5초 2차 등록 제거 — 8초 안전망만 유지(등록 안 된 경우에만 15초 후보 등록) |
| 중복 개표 방어 | `_silent_tally_if_pending`에 개표 진행 중 락(`_tally_in_progress`) — 이미 개표면 무시 |
| 피고인 팝업 10초 | 유저가 피고인일 때 찬반 팝업에 '투표권 없음' 안내 + **10초 카운트다운 후 자동 닫힘** + "찬반 투표는 AI들이 진행합니다" 안내 |
| 타이머 정리 | 개표 시 피고인 10초 타이머 취소(경합 방지) |

## 실측 (E2E)

```
유저 표 접수 → 개표 호출 정확 1회, 10초 안전망 대기 후에도 재개표 없음
피고인 팝업: '⏳ 10초 후 자동으로 닫힙니다 (10)' 렌더 → 10초 후 닫힘 안내 출력
```
