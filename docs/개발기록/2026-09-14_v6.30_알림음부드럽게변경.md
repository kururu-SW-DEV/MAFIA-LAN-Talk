# v6.30 — 알림음을 부드러운 소리로 변경 (2026-09-14)

## 계기

사용자 요청: "알림음 바꿔줘. 부드러운 소리로."

## 원인/배경

새 메시지·파일 수신 알림음이 전부 `root.bell()`(Tk 기본 벨) 호출이었는데, 이는
Windows의 "기본 삐(Default Beep)" 시스템 소리를 재생해 딱딱하게 들린다.

## 수정 (`app.py`)

`_play_notify_sound()` 헬퍼를 새로 추가해 표준 라이브러리 `winsound`로 Windows가
토스트 알림에 이미 쓰는 부드러운 알림음 별칭 `"Notification.IM"`을 비동기
(`SND_ASYNC`, UI를 막지 않음)로 재생하도록 했다. 이 별칭이 해당 PC에 없더라도
`SND_NODEFAULT`를 주지 않았으므로 Windows가 자동으로 기본 삐 소리로 대체 재생하기
때문에 무음이 되는 경우는 없다. `winsound` 자체를 못 쓰는 예외 상황(비Windows
등)에서만 기존 `root.bell()`로 되돌아간다.

메시지·파일 수신 4개 지점(`_on_msg`, `_on_gmsg`, `_on_file_recv`, `_on_gfile_recv`)의
`self.root.bell()` 호출을 전부 `self._play_notify_sound()`로 교체했다.

## 검증

- `winsound.PlaySound("Notification.IM", winsound.SND_ALIAS)` 단독 호출이 예외
  없이 실행되는 것을 직접 확인.
- 기존 회귀 스위트 2종(`test_headless.py`, `test_gui_flow.py`) 재실행, 전부 통과.
- `python -m py_compile`로 문법 확인.
- 코드 작성 중 `replace_all`로 문자열을 일괄 치환하다가 방금 추가한 헬퍼 안의
  fallback `root.bell()`까지 자기 자신(`_play_notify_sound()`) 호출로 잘못
  바뀌어 무한 재귀가 될 뻔한 것을 즉시 발견해 수정 — 최종 코드에는 재귀 없음.

## 의도적으로 하지 않은 것

- 알림음 종류를 사용자가 직접 고를 수 있는 설정 UI는 추가하지 않았다 — "부드러운
  소리로 바꿔달라"는 단발성 요청이었으므로, 필요하면 추후 설정 메뉴에 알림음 선택
  옵션을 추가하는 방향으로 확장 가능하다.
