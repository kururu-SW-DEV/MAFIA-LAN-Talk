# v6.36 — 외부 "버그 50선" 보고서 검증 및 확정 버그 7건 수정 (2026-09-14, 1차) (2026-09-14)

## 계기

사용자가 다른 세션(재미나이로 추정)이 작성한 "LAN Talk 프로그램 버그 및 결함
50선 정밀 보고서"를 그대로 전달. 항목이 구체적이고 파일:줄번호까지 명시돼
있었지만, 이번 세션 내내 "그럴듯해 보이는 남의 분석을 그대로 믿지 말고 코드로
직접 재현·반증하라"는 원칙을 지켜왔으므로, 50건 전부를 배경 에이전트 6개로
나눠 실제 현재 코드와 대조 검증했다(줄번호는 이 세션의 다른 수정들로 이미
밀려 있었음).

## 검증 결과 요약

50건 중 **약 28건이 실제 버그로 확인**됐고, 나머지는 이미 안전하게 처리돼
있거나(예: `_atomic_write_text`의 원자적 쓰기 덕에 자동폭파 파일 삭제 중
롤백이 필요 없음), 의도된 설계였거나(예: `secret.key`를 프로그램 폴더에 두는
것 — 폐쇄망 무설치 배포 원칙), 파이썬 문자열 모델에 대한 오해에 기반했거나
(UTF-16 서로게이트 절단 주장 — CPython str은 코드포인트 단위라 애초에 안
쪼개짐), 과장이었다(예: 32KB 정수 XOR을 "메모리 스파이크"라 했으나 실제로는
표준적인 고속 관용구).

## 이번 회차(1차)에서 수정한 7건

1. **아바타 경로 탈출 + 해시 위조 방지** (`engine.py`): `avatar_resp`/
   `avatar_update` 처리 시 상대가 주장하는 `av_hash`를 그대로 파일명에 써서
   `../../` 같은 값으로 avatardir 밖에 쓸 수 있었고, 실제 내용과 해시가
   일치하는지 검증도 안 했다. `_save_received_avatar()`를 새로 만들어
   **우리가 직접 복호화한 바이트의 SHA1을 계산해 그 값으로만 저장**하도록
   바꿔, 상대가 보낸 해시값 자체를 아예 신뢰하지 않게 했다(경로 탈출도
   해시 위조도 구조적으로 불가능해짐). `_check_fetch_avatar()`의 존재 확인
   경로에도 12자리 hex 형식 검증을 추가했다.
2. **Windows 예약 장치 이름 미필터링** (`netutils.py`): `safe_name()`이
   `con.txt`, `aux.png` 같은 이름을 그대로 통과시켜 저장 시 `WinError 22`가
   나던 문제. 확장자를 뗀 파일명 본체가 `CON/PRN/AUX/NUL/COM1~9/LPT1~9`와
   (대소문자 무시) 일치하면 접두사 `_`를 붙이도록 수정.
3. **임시 파일명 스레드 충돌** (`engine.py`): `_atomic_write_text`의 임시
   파일명이 PID만 사용해 같은 프로세스의 여러 스레드가 동시에 같은 경로를
   저장하면 충돌할 수 있었다. 스레드 id도 섞어 넣도록 수정.
4. **파일 저장 경로 TOCTOU 경쟁** (`engine.py`): `_unique_path()`로 빈 이름을
   찾는 것과 `shutil.move()`로 실제 옮기는 것 사이에 락이 없어, 같은 이름의
   전송 두 개가 동시에 끝나면 한쪽이 유실될 수 있었다. 이 구간을 전용 락
   (`_save_path_lock`)으로 직렬화.
5. **브로드캐스트 발견용 포트 하드코딩** (`engine.py`): `--port`로 기본값과
   다른 포트를 골라 쓰면(사무실 전체가 통일해서 쓰거나, 한 PC에서 여러
   인스턴스를 테스트할 때) 브로드캐스트 목적지 포트가 여전히 `DEFAULT_PORT`로
   고정돼 있어 서로 발견이 안 됐다. `self.port`로 보내도록 수정.
6. **로컬 IP 감지 시 `SO_BROADCAST` 누락** (`netutils.py`): 브로드캐스트
   주소로 `connect()`하기 전에 `SO_BROADCAST`를 켜지 않아 Windows에서 항상
   예외로 폴백(느린 `gethostbyname_ex` 경로)만 타고 있었다. 옵션 추가.
7. **아웃박스 재전송 시 메시지 순서 역전** (`engine.py`): `_flush_outbox`가
   한 항목이 실패해도 멈추지 않고 다음 항목을 계속 시도해, 뒤 메시지가
   앞 메시지보다 먼저 도착할 수 있었다. 실패하면 그 자리에서 멈추고 나머지는
   다음 flush(상대가 다시 온라인이 됐을 때)로 미루도록 수정 — 순서 보장.
8. **그룹 파일 전송 부분 성공을 전체 실패로 오판** + **진행률 바 요동**
   (`engine.py`, `app.py`): `all(results)`라 10명 중 9명이 성공해도
   `ok: False`였던 것을, 한 명이라도 성공하면 `ok: True`로 보고하되
   `sent_count`/`total_count`를 같이 넘겨 GUI가 "N/M명 전송 완료"를 구분해
   보여주도록 함. 병렬로 뛰는 멤버별 스레드가 같은 `fid`로 각자 진행률을
   쏘던 것도, 멤버별 진행량을 락으로 합산해 하나의 단조 증가하는 값으로
   emit하도록 고쳐 진행률 바가 80%↔10%로 튀던 현상을 없앴다.

(8번이 사실상 두 항목(보고서의 #8, #9)을 한 번에 고친 것이라 실질적으로
7개 수정에 8개 항목이 해소됨.)

## 검증

- 각 수정 직후 `python -m py_compile` + 기존 회귀 스위트 3종
  (`test_headless.py`, `test_gui_flow.py`, `smoke_gui.py`) 재실행.
- 도중 자체 회귀 발견: `_file_send_worker` 수정 중 `sent_count`를 그룹
  분기에서만 정의해뒀는데 emit 코드가 양쪽 분기 공통이라 1:1 전송 시
  `UnboundLocalError`가 났다 — `test_headless.py`가 즉시 잡아내 바로 수정.
- 아바타 저장 함수(`_save_received_avatar`)를 직접 호출해 반환된 해시가
  실제 SHA1과 일치하고 함수 시그니처 자체에 공격 가능한 `av_hash` 인자가
  없음을 확인.
- `safe_name("con.txt")` 등을 직접 호출해 예약어 회피 확인.
- 오프라인 멤버 1명을 포함한 3인 그룹으로 실제 파일 전송을 재현해
  `file_sent`가 `ok=True, sent_count=1, total_count=2`로 오는 것과, 진행률
  이벤트의 `total`이 멤버 수만큼 배율된 합산 분모로 오는 것을 직접 확인.
