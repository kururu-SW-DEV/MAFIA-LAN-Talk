# v6.38 — 이름 저장/스크롤 버그 수정, 외부 보고서 2회 검증, 팝업·모달 임베드화, 1px 렌더링 버그 수정 (2026-09-14)

## 계기

사용자가 직접 겪은 버그 2건(이름 변경 미저장, 전송한 메시지가 스크롤해야
보임) 제보로 시작해, 이어서 제미나이(Gemini)의 외부 코드 검토 보고서를
두 차례 검증·수정하고, UI를 우클릭 메뉴부터 모달 다이얼로그까지 "임베드"
방식으로 통일해 나가다가 마지막에 화면 렌더링 1px 버그의 근본 원인까지
추적해 고쳤다.

## 1. 사용자 제보 버그 2건

- **이름 변경이 재시작하면 원래대로 돌아옴** (`engine.py`): `set_name()`이
  메모리상의 `self.name`만 바꾸고 `settings.json`에 저장하지 않아, 재시작 시
  `default_name()`(윈도우 계정명)으로 되돌아갔다. `set_name()`에서 이름을
  저장하도록 추가하고, `Engine.__init__`의 이름 결정 순서를 "실행 인자 >
  저장된 이름 > 시스템 계정명"으로 수정. `app.py`에서 `Engine` 생성 시
  `default_name()`을 미리 채워 넣던 코드도 제거해 저장값이 실제로 반영되게 함.
- **메시지를 보내도 스크롤이 맨 아래로 안 내려감(스플리터 조절 시 스크롤이
  살짝 올라오는 것과 동일 버그)** (`chat_renderer.py`): `_reload_chat`이
  리드로우 **전**에 "맨 아래였는지"(`was_bottom`)를 판단해놓고도, 실제
  `force_bottom` 인자에는 반영하지 않고 있었다. 창 폭이 바뀌면(스플리터
  드래그) 말풍선이 다시 줄바꿈되며 전체 높이가 변하는데, 리드로우 **후**에
  `yview()`로 다시 판정하면 절대 스크롤 위치는 그대로여도 비율이 바뀌어
  "맨 아래가 아님"으로 오판되어 스크롤이 보정되지 않았다. 리드로우 전 판단을
  그대로 `force_bottom`에 반영하도록 수정.

## 2. 외부 보고서 검증 1회차 (Gemini) — 확정 7건 + 기각 1건

- **`MentionPopup` 바깥 클릭 감지 영구 무력화**: `dialogs.py`의 팝업 메뉴가
  닫힐 때 `unbind_all("<Button-1/2/3>")`을 호출해 전역 클릭 바인딩을 통째로
  지우는 바람에, 멘션 팝업의 바깥 클릭 감지가 한 번 겹치면 영구히 사라졌다.
  `canvas_utils.py`에 공용 디스패처 `register_outside_click()`을 새로 만들어
  시퀀스당 `bind_all`을 단 한 번만 걸고, 각 호출자는 콜백을 리스트에
  등록/해제만 하도록 통일.
- **다이얼로그 종료 시 마우스 휠 전역 언바인드**: 같은 이유로
  `canvas.unbind_all("<MouseWheel>")`가 다른 목록의 휠 스크롤까지 죽였다.
  `bind_scoped_mousewheel()`을 추가해 "지금 스크롤 대상이 어느 canvas인지"만
  갈아끼우는 방식으로 교체.
- **클립보드 DIB 파싱 오프셋 왜곡** (`netutils.py`): `bi_size >= 40`
  조건이 BITMAPV4/V5 헤더(108B/124B)까지 걸려 컬러 마스크 12바이트를
  잘못 더해 캡처 이미지가 깨졌다. `bi_size == 40`으로 좁혀 수정.
- **대화방 내 검색(Ctrl+F)에서 스티커 키워드 누락** (`chat_search.py`):
  `name`만 검색하고 `keywords` 목록을 빠뜨려 통합 검색과 결과가 달랐다.
- **그룹 공지 핀 전파 시 자기 자신 제외 누락** (`engine.py`
  `_broadcast_pin_notice`): 다른 브로드캐스트 함수와 달리 `_is_self` 체크가
  없었다. 추가.
- **DND 리훅 디바운스 타이머 종료 시 미취소** (`app.py` `_quit`):
  `after_cancel` 추가.
- **모달 다이얼로그 4곳 Escape 닫기 누락** (`dialogs.py`): 숨긴 대화/상대
  연결/브로드캐스트/멤버 초대·목록 다이얼로그에 `<Escape>` 바인딩 추가.
- **(기각) 탐색기 콘솔 깜빡임**: `explorer.exe`는 GUI 서브시스템 실행 파일이라
  `CREATE_NO_WINDOW` 유무와 무관하게 콘솔 창이 뜨지 않음 — 실제 버그 아님.

## 3. 외부 보고서 검증 2회차 (수정 코드 재검토) — 회귀 1건 + 개선 2건 + 기각 1건

1차 수정 코드 자체를 다시 검토받아 새로 유입된 회귀를 잡았다.

- **(회귀, 심각) `bind_scoped_mousewheel`/`register_outside_click`의
  `winfo_toplevel()` 버그**: 다이얼로그(Toplevel) 안의 위젯으로 호출하면
  `winfo_toplevel()`이 그 다이얼로그 자신을 반환해서, 다이얼로그를 열 때마다
  별개의 "root"에 상태를 만들고 `bind_all`을 다시 걸어 메인 창 디스패처를
  덮어쓰고, 다이얼로그가 닫히면 메인 창 스크롤이 죽은 디스패처만 참조하게
  됐다. `_root()`(Toplevel을 몇 겹 거치든 항상 진짜 앱 루트로 귀결)로 교체.
- **embed=True 메뉴(헤더 `+`/설정)에서 Escape 미동작**: `if not embed:`
  조건 때문에 임베드 메뉴만 Escape 바인딩이 빠져 있었다. 조건 제거.
- **`MentionPopup`이 앱 밖 클릭에는 안 닫힘**: 앱 전체가 포커스를 잃으면
  (다른 프로그램 클릭) 같이 닫히도록 `<FocusOut>` 처리 추가.
- **(기각) `_build_picker_list`의 `<Destroy>` 필터 누락**: `parent`가
  다이얼로그의 `win` 자신이고 재호출 루프도 없어, 필터가 없어도 자식 위젯
  파괴가 부모로 전파되지 않으므로 실제 버그 아님으로 확인.

## 4. UI 임베드화 (별도 OS 창 → 본창 안쪽으로)

- **채팅·친구 목록 우클릭 메뉴 및 "카테고리 지정" 하위 메뉴**
  (`app.py` `_show_row_menu`, `_open_category_menu`): `_popup_menu(...,
  embed=True)`로 전환.
- **이름 변경 / 내 IP 확인 창**: `_prompt_text`/`_alert`(별도 Toplevel,
  `wait_window` 블로킹) 대신 본창 안에 배경 차단막 + 패널로 뜨는
  `_embed_prompt_text`/`_embed_alert`를 `dialogs.py`에 새로 구현.
  - 최초 구현은 배경을 Canvas + `stipple="gray50"`로 반투명처럼 그리려
    했으나, 이 Windows Tk 빌드에서 격자 대신 완전한 단색 검은 사각형으로
    렌더링돼 패널이 그 밑에 가려 **화면이 통째로 새까맣게 보이는 버그**가
    발생했다. 즉시 단색 Frame(C_MAIN) 방식으로 교체하고 `panel.lift()`를
    추가해 재발을 막았다.
- **대화방 이름 변경 / 대화 상대 별칭 변경** (`dialogs.py`
  `_rename_conversation_dialog`): 본창에서 바로 열 때(`parent=None`)는
  임베드 모달을, 다른 다이얼로그 안에서 열 때(`parent=win`)는 기존 Toplevel
  방식을 쓰도록 분기 — 임베드는 본창(`self.root`) 기준으로 뜨기 때문에 다른
  Toplevel 위에서 열면 뒤에 가려 보이지 않는 문제를 피하기 위함.

## 5. 창 상단 1px 흰 점 렌더링 버그 (근본 원인 추적)

사용자가 스크린샷으로 제보한, "대화를 선택하세요" 위쪽 사이드바/헤더 경계에
생기는 1픽셀짜리 흰 점.

- **1차 시도(실패)**: DWM 창 테두리 색(`DWMWA_BORDER_COLOR`, 속성 34)이
  캡션 색과 별개로 설정 안 된 게 원인이라 추정하고 `winapi.py`
  `apply_dark_titlebar`에 추가했으나, 사용자 재확인 결과 여전히 재발.
- **원인 재추적**: 격리된 재현 스크립트(`_shell_repro*.py`)를 만들어
  computer-use로 실제 화면을 스크린샷/줌해 가며 비교한 끝에, 문제가 OS
  창 테두리가 아니라 **앱 내부 위젯 경계**에서 나는 것을 확인. 이어서 PIL
  `ImageGrab`으로 창의 실제 픽셀을 직접 스캔하는 스크립트로 전환해, 캡처
  타이밍(5~700ms)을 바꿔가며 원인을 특정했다.
  - `apply_dark_titlebar`가 다크 모드/캡션색 적용 후 호출하는
    `SetWindowPos(..., SWP_FRAMECHANGED)`가 Tk의 위젯 그리기보다 먼저
    실행되면, 그 순간의 미완성 화면(Windows 기본 배경색)이 그대로
    캡처되는 레이스 컨디션이었다.
  - A/B 테스트로 확정: 수정 전 코드는 캡처 시점 5~15ms일 때 사이드바/헤더
    경계 전체가 밝은 회색(`#e3e8ec` 부근) 블록으로 매번 검출됐고, 30ms
    이후에는 Tk의 후속 리드로우로 사라졌다(대부분의 실행에서 눈에 안 띄는
    이유). 수정 후에는 5~700ms 전 구간에서 0건.
- **수정**:
  - `winapi.py` `apply_dark_titlebar`의 `_apply()` 맨 앞에
    `win.update_idletasks()`를 추가해, 강제 리페인트 전에 Tk가 대기 중인
    그리기를 먼저 끝내도록 함(핵심 수정).
  - `app.py`: `apply_dark_titlebar()` 호출 위치를 `_build_shell()`(자식
    위젯 생성) **이후**로 이동 — 애초에 빈 창 상태에서 리페인트가 걸리지
    않도록 하는 보조 안전장치.

## 검증

- 매 수정 직후 `python -m py_compile`로 전체 수정 파일 컴파일 확인.
- 1px 흰 점은 격리된 재현 스크립트 + PIL 픽셀 스캔으로 수정 전/후를
  5~7개 타이밍 지점에서 반복 실행해 실제 재현·해결을 정량적으로 확인
  (수정 전: 이른 타이밍에서 매번 검출 / 수정 후: 전 구간 0건).
- 테스트에 사용한 임시 스크립트(`_shell_repro*.py`, `_shell_pixelscan*.py`)와
  캡처 이미지는 작업 종료 후 모두 삭제, 테스트 중 실수로 띄운 여벌 앱
  인스턴스도 종료 처리.

## 남은 항목

- `_prompt_text`/`_alert`를 쓰는 나머지 다이얼로그(카테고리 이름, 방화벽
  안내 등)는 이번 임베드화 범위에서 제외했다. 필요 시 동일한 패턴으로
  마저 전환 가능.
