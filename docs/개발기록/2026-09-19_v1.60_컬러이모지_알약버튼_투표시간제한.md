# v1.60 — 컬러 이모지 렌더링 + 게임바/팝업 알약 버튼 디자인 + 투표·밤행동 제한시간 (2026-09-19)

## 사용자 지적 흐름 (요약)

1. "마피아 게임방 - [게임시작]을 누르세요" 안내 문구가 실제 진행(참가자 모집 →
   게임 시작 2단계)과 다르다.
2. 참가자 모집 지나서 게임 시작하고 토론 중인데 하단 상태 표시줄은 예전 문구
   그대로다.
3. "'투표이름'으로 지목" 멘트를 "자유롭게 토론하세요"로 수정.
4. 이모지가 칼라로 안 나온다(Tk 렌더링 한계) — 상단바부터 시작해서 팝업들까지
   순차적으로 확장.
5. 상단바 버튼 간격/여백/모서리(둥글게)/높이 통일.
6. "[게임 진행 중]" 버튼에 격자무늬(Tk의 disabled 스티플)가 씌워짐.
7. 게임바 배경이 밤/변론 테마로 바뀌면 버튼 라벨이 사라지는 버그.
8. 밤 테마일 때 단계 표시 라벨만 배경색이 안 맞음.
9. "직업 공개 — 루카 (citizen이었습니다)" — 영문 역할 키가 그대로 노출됨.
10. 최후 변론 찬반 투표/밤 행동(마피아 살해·의사 치료·경찰 조사)도 시간
    제한(15초) 두고, 시간 안에 선택 안 하면 선택 안 한 걸로 처리.
11. 찬반 투표 팝업 두 버튼 크기 비대칭 → 대칭으로.
12. "멈춘 아님" 오탈자.
13. 직업 안내 팝업 "확인" 버튼 크기 확대.

## 1. 안내 문구 실측/동기화 버그 수정 (`mafia_ui.py`)

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| 게임방 진입 상태줄 | "[게임 시작]을 누르세요" | "[참가자 모집]을 누르세요" (실제 1단계 버튼과 일치) |
| 빈 방 안내 | "[게임 시작]을 누르면 역할 배정" | "[참가자 모집] → [게임 시작]" 2단계 흐름 명시 |
| 낮 토론 단계 표시(2곳) | "'투표 이름'으로 지목" | "자유롭게 토론하세요" |
| "멈춘 아님" | 비문 | "멈춘 것 아님" |

**하단 상태 표시줄이 갱신 안 되던 근본 원인**: 하단 `self.status`는 방 진입 시
1회, 피고인 변론 시 1회만 `set()`되고, 이후 토론/밤/개표 등 단계 전환 때는
전혀 갱신되지 않았다. `refresh_mafia_phase_label()`(상단 라벨 갱신 지점, 게임
전 단계 전환마다 이미 호출되고 있었음)이 하단 `self.status`도 같이 갱신하도록
수정 — 마피아 방을 보고 있을 때만 덮어써서 다른 채팅방에는 영향 없음.

## 3. 컬러 이모지 렌더링 인프라 신설 (`emoji_render.py`)

Tk는 텍스트를 항상 `fg` 색 하나로만 그려서 컬러 이모지 폰트(Segoe UI Emoji)를
넣어도 단색으로 뭉개진다(Tk 자체 한계). 문자열을 이모지/일반 텍스트 구간으로
나눠 PIL로 각각 알맞은 폰트로 그리고(이모지는 `embedded_color=True`) 투명
배경 RGBA 이미지로 합성하는 모듈을 신설:

- `render_mixed_text` / `has_emoji` / `apply(widget, font)`: Label 하나를
  즉석에서 컬러 이모지로 다시 그림 — 로비 역할 팝업 아이콘, 시네마틱 배너
  아이콘/제목, 찬반·투표 팝업의 카운트다운·진행률 라벨 등에 적용.
- `enable_color_emoji(widget, ...)`: `.config/.configure`를 감싸서 이후
  `text=`로 들어오는 문자열에 이모지가 있으면 자동으로 컬러 이미지로 치환.
  호출부(기존 코드)는 손댈 필요 없음.
- 이모지 색 검출 범위에 시계류(⏳ 등, U+2300~23FF)와 ZWJ(복합 이모지 연결
  문자, 예: 🧑‍🌾)가 빠져 있던 걸 발견해 추가.

## 4. 게임바/팝업 둥근 모서리 알약 버튼 (`enable_pill_button` / `make_pill_button`)

Tk 버튼은 각진 사각형만 그릴 수 있어서, 배경색+글자를 통째로 둥근 사각형
이미지로 그려 얹고 실제 위젯 배경은 부모(게임바)와 항상 똑같이 맞춰 투명하게
보이게 하는 방식으로 구현. `make_pill_button()` 팩토리로 팝업 어디서든 한
줄로 생성 가능하게 만들고 아래에 순차 적용:

- 상단 게임바 5개 버튼(게임설정/직업확인/모집취소/참가신청/게임시작)
- 최후 변론 찬반 투표 버튼(🔪 처형 찬성 / 🕊 만류), 피고인 화면 확인 버튼
- 투표/재투표 팝업의 후보 버튼, 기권 버튼
- 밤 행동 팝업(마피아 살해/의사 치료/경찰 조사) 후보 버튼
- 역할 안내 팝업 "확인 (비밀 유지)" 버튼

부수 개선:
- **간격/여백**: 버튼 내부 여백(`pad_x=16, pad_y=4~10`)과 버튼 사이 간격을
  넉넉하게 재조정.
- **높이 통일**: 이모지 글리프는 폰트 크기가 같아도 문자마다 실제 비트맵
  높이가 들쭉날쭉해서(📢 vs ⚙ vs 🃏), 공식으로 어림잡지 않고 실제 쓰일 모든
  문구를 한 번씩 그려보고 최댓값을 구하는 `measure_content_height()`를 만들어
  `min_content_h`로 공통 적용 — "[게임 진행 중]"처럼 이모지 없는 문구만 유독
  낮아 보이던 문제 해소.
- **폭 대칭**: 찬반 투표 두 버튼("처형 찬성" vs "만류")처럼 글자 길이가 다른
  경우, 더 넓은 쪽 폭을 재서 `min_w`로 공통 적용해 좌우 대칭 유지.
- **직업 팝업 확인 버튼 확대**: 글자 11→15pt, 여백 20×6→28×12 (128×29 →
  172×45px).

## 5. 버그 3건 (알약 버튼 도입 과정에서 발견)

| 버그 | 원인 | 수정 |
|---|---|---|
| **"[게임 진행 중]" 버튼에 격자무늬(베일)** | `state="disabled"`를 실제로 걸면 Tk가 이미지 위에 자동으로 회색 스티플을 씌운다(알파 무시, 사각형). | 실제 Tk `state`는 항상 `"normal"`로 고정하고, 클릭 차단은 `command`를 비웠다 복원하는 방식으로 대체. 비활성 중 호버로 색이 원복되는 것도 방지. |
| **밤/변론 테마 전환 시 버튼 라벨이 사라짐** | 배경 동기화 헬퍼가 `w.config(text=w.cget("text"))`로 재도색을 시도했는데, 알약 버튼은 실제 Tk `text`를 항상 빈 문자열로 비워두고(글자는 이미지 안에만 있음) 진짜 문구는 클로저에만 저장 — `cget("text")`가 항상 빈 문자열을 반환해 빈 알약만 남았다. | `enable_pill_button`이 `_pill_redraw`(텍스트 그대로, 재도색만)를 위젯에 노출하도록 하고 호출부가 그걸 쓰도록 수정. (이후 `cget`/`__getitem__` 자체도 논리적 값을 반환하도록 오버라이드해 근본적으로 해소) |
| **밤 테마일 때 단계 표시 라벨만 배경 불일치** | `mafia_phase_lbl`은 게임바의 자식이지만 자기 배경을 따로 갖고 있는데, 밤 테마 전환이 게임바 배경만 바꾸고 라벨 배경은 그대로 뒀다. | `_set_night_theme`에서 게임바 배경을 바꿀 때 라벨 배경도 같이 맞추도록 수정. |

## 6. 최후 변론 찬반 / 밤 행동 선택 제한시간 15초 (`mafia_config.py`, `mafia_ui.py`)

- `DEFENSE_VOTE_WINDOW = 15`, `NIGHT_ACTION_WINDOW = 15` 신설.
- **찬반(처형여부) 투표**: 이미 있던 안전망(`_force_resolve_defense`, 시간
  안에 안 누르면 기권=반대 취급 → 부결 쪽)의 창을 기존 30초 → 15초로 단축.
  팝업에 실시간 카운트다운 라벨을 추가하고, 시간이 다 되면 안내 메시지 후
  팝업만 정리(실제 표 강제 처리는 기존 안전망이 그대로 담당 — 판정 로직
  이중화로 인한 충돌 방지).
- **밤 행동(마피아 살해/의사 치료/경찰 조사)**: 3개 팝업 공통으로 15초
  카운트다운을 추가. 시간 초과 시 "이번 밤은 행동하지 않은 걸로 처리됩니다"
  안내 후 팝업만 닫는다 — 실제 "선택 안 함" 처리는 원래도 core에 아무것도
  기록 안 되는 것으로 자연히 처리되던 것이라 새 판정 로직을 만들지 않았다
  (기존 30초 밤 전체 타이머와 이중 판정 시 충돌 위험 회피).
- **충돌 방지 안전장치**: 이 코드베이스는 팝업 하나가 뜨면
  `self._mafia_overlay_close`를 완전히 새 클로저로 갈아치우는 구조라, 이전
  팝업의 카운트다운 타이머가 정리 안 된 채 남아 있으면 나중에 뜬 엉뚱한
  팝업을 잘못 닫아버릴 위험이 있었다. `_wrap_overlay_close_with()`를 신설해
  오버레이가 **어떤 이유로든** 닫힐 때 항상 내 타이머도 같이 취소되도록
  했다 — 유저가 직접 선택, 시간 초과로 스스로 닫힘, 다른 팝업이 밀어내고
  뜸 세 가지 경로를 실제 Tk 이벤트 루프로 직접 테스트해 확인.
