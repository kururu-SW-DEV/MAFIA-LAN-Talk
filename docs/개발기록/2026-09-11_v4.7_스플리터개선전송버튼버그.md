# v4.7 스플릿 바 숨기기 핸들 확대/개선 & 작은 창 전송 버튼 가려짐 해결 (2026-09-11)

- **스플릿 바 접기/숨기기 버튼 클릭 편의성 대폭 개선**:
  - 기존 문제: 스플리터 기둥(`width=5`) 내부에서 핸들 버튼이 12px 크기로 배치되어 실제로는 5px 너비로 잘려 마우스 클릭이 극도로 어려웠던 문제를 근본 해결.
  - 개선: 버튼을 부모 프레임의 클리핑을 받지 않는 최상위 플로팅 위젯으로 재배치하고, 버튼 크기를 가로 24px, 세로 56px (`font=(FONT_FAM, 9, "bold")`)로 대폭 확대.
  - 사이드바 표시 시: 스플리터 기둥 중앙에 정확히 중앙 정렬(`width=24, height=56`)되어 넉넉한 클릭 영역 제공.
  - 사이드바 숨김 시: 창 좌측 경계선(`x=0`)에 정확히 밀착(`width=26, height=56`, 선명한 티타늄 블루 화살표 `▶`)되어 서랍 손잡이처럼 원클릭으로 열 수 있도록 배치.
  - 스플리터 기둥 더블클릭(`Double-Button-1`) 지원: 버튼을 정밀하게 조준하지 않고도 기둥 아무 곳이나 더블클릭하면 즉시 사이드바가 접히고 열리도록 편의성 추가.
- **작은 창에서 전송 버튼이 사라지던 버그 근본 해결**:
  - 기존 문제: `inner` 입력 프레임에서 `self.entry(tk.Text)`가 `self.send_btn`보다 먼저 `pack(side="left", fill="both", expand=True)`으로 배치되었고, `tk.Text`의 기본 요구 너비(80글자 ≈ 640px) 때문에 창 너비가 450px 이하로 좁아지면 `entry`가 공간을 독점하여 `send_btn`이 1x1 픽셀로 압축되며 화면 밖으로 밀려나 매핑되지 않음(`winfo_ismapped() == 0`).
  - 개선: `send_btn`을 `side="right"`로 `entry`보다 먼저 패킹하여 우측 끝 공간을 절대적으로 보장. `entry`는 `width=1`로 최소 기본 요구 너비를 설정하여 첨부 버튼과 전송 버튼 사이의 남은 공간에 유연하게 맞춰지도록 변경.
  - 세로 크기 축소 방어: `body`에서 하단 입력 위젯(`cnt`, `statuslbl`, `row`)을 `chat_wrap.pack(fill="both", expand=True)`보다 먼저 `side="bottom"`으로 패킹하여 창 높이를 극단적으로 줄여도 입력창과 전송 버튼이 절대 잘리지 않도록 구조 개선.
  - 창 크기 동적 반응: `_on_root_resize`에서 창 너비가 좁아질 때(예: 360px) 사이드바가 화면의 과도한 비율을 차지하지 않도록 최대 46% ~ 55%로 유연하게 제한하여 대화창 입력 영역 확보.
- 검증: `test_new_features.py`(450x800, 360x540, 300x400 전송 버튼 표시 및 스플리터 핸들 크기 24x56 검증), `smoke_gui.py`, `test_headless.py`, `test_gui_flow.py` 전 테스트 무인 통과.
