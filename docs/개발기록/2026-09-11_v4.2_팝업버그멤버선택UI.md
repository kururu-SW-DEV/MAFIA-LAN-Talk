# v4.2 팝업 메뉴 닫힘 버그 수정 + 멤버 선택 UI 개선 (2026-09-11)

- **우클릭/[＋] 팝업이 바깥을 클릭해도 안 닫히던 버그**: v4.1에서 커스텀 팝업으로 바꾸며
  `grab_set()` + `<FocusOut>` 조합으로 닫히게 했었는데, 사용자 실측 결과 전혀 안 닫혔다.
  원인은 두 가지 조합: (1) `overrideredirect(True)` 창은 Windows에서 `<FocusOut>`이 안정적으로
  발생하지 않고, (2) `grab_set()`은 오히려 바깥 클릭을 이 창으로 흡수해버려 "바깥을 눌러도
  반응이 아예 안 감"에 가까웠다. `grab_set` 없이 `root.bind_all("<Button-1/2/3>", ...)`로 클릭
  좌표가 팝업 영역 바깥이면 직접 닫는 방식으로 교체. 단, 메뉴를 여는 바로 그 클릭 이벤트
  안에서 새 바인딩이 곧바로 걸려버리면 자기 자신을 열자마자 닫아버리는 재귀적 문제가 생겨
  (Tk가 같은 이벤트 디스패치 중 새로 추가된 bind_all을 그 자리에서 적용하는 특성), `win.after(1, ...)`로
  다음 이벤트 루프 틱까지 바인딩 등록을 미뤄 회피. 자동화 테스트로 "바깥 클릭 시 닫힘/Escape로
  닫힘/항목 클릭 시 정상 동작+닫힘" 3가지를 모두 재현·확인.
- **그룹 멤버 선택 UI가 "너무 심심하다"는 피드백**: 기존엔 그냥 `tk.Checkbutton` + 텍스트 한 줄
  나열이었다. 사이드바 친구 탭과 같은 모양(아바타 원+이니셜+온라인 점, 이름, IP:포트 부제목)의
  행으로 재작성하고, 체크박스 대신 오른쪽에 원형 인디케이터(선택 시 파란 원+흰 체크마크, 행
  배경도 옅은 파랑으로 강조)를 넣은 `_build_picker_list()` 공용 헬퍼로 통합 — "새 그룹 만들기"와
  "멤버 추가" 두 다이얼로그가 이 헬퍼를 공유한다.
  - 이 작업을 스크린샷으로 검증하는 과정에서 실제 버그를 하나 더 발견: 체크 인디케이터를 다시
    그리는 `_redraw_check()` 함수가 `chk`/`v`를 클로저 자유변수로 참조하고 있어서, for 루프가
    다 돌고 난 뒤(즉 실제로 클릭이 발생하는 시점)에는 모든 행의 `_redraw_check`가 "루프의 마지막
    행"의 캔버스/변수를 가리키는 고전적인 "루프 안 클로저" 버그였다. 배경색 토글은 `_toggle`이
    자체적으로 기본인자(`v=v, widgets=widgets`)로 올바르게 바인딩해 정상 작동했지만, 체크마크만
    엉뚱한(마지막) 행에 그려지는 상태였음 — 스크린샷 없이는 놓쳤을 버그. `_redraw_check(chk=chk,
    v=v)`로 동일하게 기본인자 바인딩해 해결.
- 검증: 자동화 스크린샷에 "실제 앱의 정확한 포인트 컬러(#3390ec) 픽셀이 존재하는가"를 자체
  검사해 엉뚱한 창(사용자의 실제 브라우저 등)을 잘못 캡처했을 때 즉시 버리고 재시도하는 절차를
  적용(이전에도 몇 차례 다른 창을 잘못 캡처하는 사고가 있었음). 3종 무인 테스트 전부 회귀 없이 통과.
