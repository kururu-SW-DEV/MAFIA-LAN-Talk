# v4.0 대화 삭제 + 친구 탭 + 파일/사진 전송 (2026-09-11)

- 계기: v3 배포 직후 사용자가 이어서 (1) 좌측 대화 목록에서 대화 삭제 (2) 대화 목록과 분리된
  "친구목록" 탭 (3) 채팅창 파일 전송(사진은 인라인, 일반 파일은 카카오톡식 파일카드) + 다운로드
  폴더 설정 가능을 요청. 확인된 방향: 이미지 미리보기는 tkinter가 자체 디코딩 가능한 PNG·GIF·BMP만
  지원(Pillow 등 외부 패키지 추가는 이 프로젝트의 핵심 원칙에 위배되어 거부) — JPG 등은 파일카드로
  대체. 대화 삭제는 목록 숨김만(기록 보존, 재메시지 시 자동 재등장). 친구 탭은 별도 "추가" 조작 없이
  현재 사내망에서 보이는 모든 동료를 자동 표시.
- **대화 삭제(숨김)**: `Engine.hidden` 집합을 `settings.json`에 영속화(`hide_key`/`unhide_key`/
  `unhide_all`). 여러 곳에서 같은 `settings.json`을 쓰게 되면서 동시 쓰기로 서로 덮어쓰는 위험이
  생겨 `_update_settings()` 공용 헬퍼(읽기→콜백 수정→쓰기를 락 하나로 묶음)로 정적 IP·숨김 목록·
  다운로드 폴더 저장을 통일했다. 목록 행 우클릭 → "대화 삭제". 상대의 새 메시지 수신 시(`_on_msg`/
  `_on_gmsg`) 숨김이면 자동 해제 — 사용자가 다시 대화를 걸어오면 알아서 살아나야 한다는 요구사항.
- **친구 탭**: 사이드바에 "채팅"/"친구" 토글 버튼 2개 추가. `_refresh_list()`를 탭 분기 하나로
  유지하면서(키 기반 diff 갱신 구조는 그대로 재사용) "친구" 탭은 `engine.peers`를 이름순으로 나열,
  그룹은 표시 안 함. 최초 설계는 "친구 탭은 숨김과 무관하게 항상 표시"였으나, 곧이어 사용자가
  "채팅 탭과 친구 탭 둘 다 목록을 지울 수 있게 해달라"고 요청해 재설계 — 친구 탭도 동일한
  `hidden` 집합을 그대로 적용받도록 바꾸고(우클릭 메뉴 라벨만 탭에 따라 "대화 삭제"/"친구 목록에서
  삭제"로 다르게 표시), 대신 "＋" 메뉴의 "숨긴 대화 모두 표시"가 두 탭 모두를 위한 공용 복구
  수단이 되도록 정리했다. 삭제 강도는 "다시 연락오면 자동 복귀"로 확정(차단/영구 무시 개념은
  도입하지 않음 — 요청 확인 후 결정).
- **파일·사진 전송**: 서버가 없으므로 1:1은 상대에게, 그룹은 멤버 전원에게 개별 유니캐스트로
  파일을 보낸다. 신규 패킷 `file_offer`(메타데이터)·`file_chunk`(32KB씩 base64 인코딩, **순차** 전송 —
  이전 청크의 ACK를 받아야 다음 청크를 보냄, 속도보다 단순성·신뢰성 우선). 기존 `_send_reliable`을
  블로킹 버전 `_send_reliable_wait`으로 추출해 파일 워커 스레드가 청크마다 동기적으로 기다리도록
  재사용(비동기 버전은 이 블로킹 버전을 스레드로 감싸는 얇은 래퍼로 재정의 — 기존 메시지 전송 동작
  변화 없음, 회귀 테스트로 확인). 최대 20MB 제한, 초과 시 `send_file()`이 즉시 `ValueError`.
  - 수신측은 청크를 메모리에 모으다 전량 도착 시 조립해 `Engine.download_dir`(기본
    `datadir/downloads`, `set_download_dir()`로 변경 가능)에 저장. 파일명이 겹치면 `이름 (1).ext`로
    자동 넘버링. 대화 기록에는 `{"kind":"file", ...}` 레코드를 기존 텍스트 로그 파일에 함께 저장
    (`load_history`/`load_group_history`의 필터 조건을 `"text" in rec or "kind" in rec`로 확장 —
    기존 텍스트 전용 레코드와 하위 호환 유지).
  - GUI 렌더링은 기존 Canvas 말풍선 파이프라인(`_draw_record`)에 `kind` 분기만 추가하는 방식으로
    구현: 이미지는 `tk.PhotoImage(file=path)`로 직접 로드 후 정수 배율 `subsample()`로 축소해
    `create_image`, 실패하거나 이미지가 아니면 문서 아이콘+파일명+용량이 담긴 둥근 카드로 폴백.
    두 경우 모두 클릭하면 `os.startfile()`로 기본 프로그램이 열림(텍스트 말풍선의 "클릭=복사"와는
    다른 동작이라 README에 명시).
  - 실측으로 잡은 버그: `group_invite` 처리 순서상 `_upsert_group()`(그룹을 `engine.groups`에 등록,
    이 시점부터 `gid in engine.groups`가 참이 됨)이 `_merge_group_history()`(이력 스냅샷을 로그
    파일에 기록)보다 먼저 실행되고 있었다. 두 작업 사이의 짧은 틈에 이력을 읽으면 "그룹은 이미
    보이는데 최근 대화 스냅샷은 아직 비어 있는" 경합이 생겨, 뒤늦게 합류한 멤버 테스트가 10회 중
    2회꼴로 간헐 실패했다. 이력 병합을 그룹 등록보다 먼저 실행하도록 순서를 바꿔 해결(15회 연속
    재현 없음 확인) — v3에서 고친 사이드바 diff 갱신 경합과 같은 종류의 "가시성과 완료 시점이
    어긋나는" 패턴이라 기록해 둔다.
- **좌상단 아이콘 교체**: 기본 Tk/파이썬 아이콘 대신 종이비행기 모양의 파란 아이콘을 새로 그려
  `iconphoto()`로 적용(16/32/48px 각각 base64 PNG로 소스에 내장, 아이콘 생성 자체는 개발 스크립트에서
  1회 Pillow로 만들고 결과만 심었을 뿐 런타임은 여전히 `tkinter.PhotoImage`만 사용 — 표준 라이브러리
  원칙 유지). 처음 삽입 시 48px 데이터가 수작업 줄바꿈 과정에서 깨져 있던 것을 디코드 검증으로
  발견·프로그램적으로 재생성해 수정. `.bat` 파일 자체는 아이콘을 가질 수 없는 Windows 제약이 있어,
  커스텀 아이콘이 붙은 `.lnk` 바로가기(`사내메신저.lnk`)를 PowerShell `WScript.Shell` COM으로 별도
  생성해 제공.
- 검증: `test_headless.py`(파일 전송 프로토콜 4단계 케이스 추가, 8회 연속), `test_gui_flow.py`(대화
  숨김·재등장·친구탭·실제 `[+]` 첨부 버튼 경로로 파일카드/PNG 인라인 렌더까지 30개 체크, 6회 연속),
  `smoke_gui.py`(탭 UI 조립 확인) 전부 통과.
