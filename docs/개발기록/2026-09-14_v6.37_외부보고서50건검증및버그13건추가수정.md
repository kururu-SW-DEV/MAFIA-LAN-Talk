# v6.37 — 외부 "버그 50선" 보고서 검증 및 확정 버그 13건 추가 수정 (2차) (2026-09-14)

## 계기

v6.36(1차)에 이어, 확정된 나머지 버그들을 우선순위대로 이어서 수정했다.

## 수정한 항목

### 보안/UX (3건)
- **실행 파일 클릭 시 경고 없이 즉시 실행** (`chat_renderer.py`, `constants.py`):
  대화창에서 받은 파일을 클릭하면 확장자 상관없이 바로 `os.startfile()`을
  호출했다. `.exe/.bat/.cmd/.vbs/.ps1` 등 위험 확장자(`RISKY_FILE_EXTS`) 목록을
  새로 만들어, 해당 확장자는 실행 전 "출처를 신뢰할 수 없다면 악성 코드일 수
  있습니다" 확인창을 한 번 거치도록 했다.
- **클립보드 파일 Ctrl+V 시 확인 없이 즉시 전송** (`app.py`): 텍스트를
  붙여넣으려다 실수로 Ctrl+V를 눌러도, 클립보드에 복사돼 있던 파일이 그대로
  상대에게 전송되고 있었다. 단, 캡처 도구(ScreenClip)로 찍은 임시 스크린샷은
  원래 취지(캡처 후 바로 붙여넣기)대로 확인 없이 그대로 두고, 탐색기에서 복사한
  "일반 파일"일 때만 파일 목록을 보여주고 한 번 확인받도록 구분했다.
- **폴더 여러 개 드롭 시 확인창이 개수만큼 연속으로 뜸** (`dnd_handler.py`):
  폴더 10개를 한꺼번에 드래그하면 "폴더는 전송할 수 없습니다" 알림이 10번
  연달아 떠서 그때마다 확인을 눌러야 했다. 건너뛴 폴더 이름을 전부 모아
  한 번만 알리도록 수정.

### 리소스 누수 (1건, 2건은 조사 후 손대지 않음)
- **`canvas_utils._smooth_circle_cache` 상한 없음**: 이미 고친 `_avatar_img_cache`와
  똑같은 패턴으로 128개 상한 + FIFO 제거를 추가했다. 다만 이 캐시의 키 공간은
  고정된 아바타 색상 팔레트 × 소수의 크기라 실질적으로는 원래도 작게
  유지됐다는 점은 확인 후 기록해둔다(방어적 보강 성격).
- **작업표시줄/트레이 아이콘 핸들에 `DestroyIcon` 미호출**: 보고서(#39, #40)가
  맞게 지적했지만, 두 곳 다 프로세스 생애주기 동안 **딱 한 번**만 호출되고
  (창 생성 1회, 앱 종료 1회), Windows가 프로세스 종료 시 모든 GDI 핸들을
  자동 회수하므로 실질적 누수가 아니다. 오히려 `apply_window_icon`의 경우
  `WM_SETICON`/`SetClassLong`으로 이미 등록해 계속 쓰고 있는 핸들을 destroy하면
  아이콘이 사라지거나 깨지는 실제 회귀를 만들 위험이 있어 **손대지 않기로
  판단**했다.

### 검색/스티커 (3건)
- **스티커 키워드 단순 부분 일치로 오검출** (`stickers.py`): "피아니스트"를
  입력하면 "아니"(NO 스티커) 키워드가 부분 문자열로 걸려 엉뚱하게
  추천됐다. `\b` 단어 경계를 요구하도록 정규식으로 교체(파이썬 정규식은
  한글도 `\w`로 인식해 한글 단어 경계에도 정상 동작). 부작용으로 "아니야"처럼
  조사/어미가 붙은 형태는 더 이상 안 잡히는데, 오검출보다는 나은 트레이드오프로
  판단해 그대로 뒀다(형태소 분석기 도입은 이 프로젝트의 "표준 라이브러리만"
  원칙에 맞지 않음).
- **대화방 내 검색(Ctrl+F)이 스티커를 전혀 못 찾음** (`chat_search.py`):
  스티커 레코드에는 `text`/`fname` 필드가 없어 검색 대상에서 항상 빠졌다.
  스티커 레코드일 때는 `sticker_id`로 스티커 이름("축하", "감사" 등)을 찾아
  검색 대상 텍스트로 쓰도록 수정.
- **검색 중 새 메시지가 오면 검색 결과가 갱신 안 됨** (`chat_search.py`,
  `app.py`, `chat_renderer.py`): `_active_chat_records`에 새 레코드를 추가하는
  5곳(메시지·파일·스티커 수신)이 전부 `_search_matches`는 그대로 둬서, 검색
  중 도착한 메시지가 검색어와 일치해도 결과에 안 잡혔다. 5곳 모두 새 헬퍼
  `_append_active_record()`를 거치도록 통일해, 검색창이 열려 있고 검색어가
  있으면 자동으로 재검색하도록 했다.

### 멘션/팝업 UI (3건, 1건은 재검토 후 범위 축소)
- **1:1 대화에서도 쓸데없이 뜨는 `@` 멘션 자동완성 팝업** (`app.py`): 상대가
  한 명뿐이라 지목할 의미가 없는데도 이메일 주소 등을 입력할 때 방해가 됐다.
  1:1 대화에서는 후보를 아예 만들지 않도록 해당 분기를 제거.
- **`MentionPopup`이 바깥 클릭으로 안 닫힘** (`widgets.py`): 채팅창이나 다른
  창을 클릭해도 팝업이 화면에 계속 남아 있었다. `dialogs.py`의 기존 팝업 메뉴와
  같은 방식(바깥 클릭 감지 후 닫기)을 재사용해 추가.
- **그룹 만들기 창에서 Enter/Escape 미작동** (`dialogs.py`): 이름을 입력하고
  Enter를 눌러도 생성이 안 되고 Escape로 닫을 수도 없었다. 두 바인딩 추가.
- **로컬 별칭으로 멘션 시 상대에게 알림 불발 (#24, 재검토)**: 코드를 다시
  읽어보니, 그룹 채팅의 `@` 자동완성은 이미 별칭이 아니라 **상대의 실제
  네트워크 이름**으로 후보를 만들고 있어(`app.py`의 `_check_mention_trigger`),
  자동완성으로 멘션하는 정상적인 경로에서는 보고서가 우려한 문제가 재현되지
  않는다. 자동완성을 쓰지 않고 사용자가 직접 로컬 별칭을 손으로 타이핑하는
  드문 경우에만 남는 훨씬 좁은 엣지 케이스로 재평가해, 프로토콜을 바꾸는
  큰 작업 대신 이번 회차에서는 보류했다.
- **팝업 메뉴가 창 리사이즈를 못 따라감(#31), 다중 발송 타이머 메뉴 위치
  하드코딩(#34)**: 코드 확인 결과 후자는 이미 `min(y, sh-h-4)` +
  `max(0,y)`로 화면 밖으로 나가거나 깨지는 것은 막혀 있어(화면 맨 위에
  붙는 정도의 시각적 흠일 뿐) 우선순위를 낮춰 이번 회차에서는 보류했다.

## 검증

- 각 수정 직후 `python -m py_compile` + 회귀 스위트 3종 재실행, 매 배치
  전부 통과.
- `match_keywords("피아니스트")`가 빈 리스트를, `match_keywords("아니")`가
  `["no"]`를 반환하는 것을 직접 호출해 확인.
- `_smooth_circle_cache`/`_avatar_img_cache`와 동일하게 128개 상한이 걸려
  있는지 코드로 확인.
