# v6.41 — 다이얼로그 4곳 임베드화, 파일 크기 설정 재배치, 작업표시줄 깜빡임, 최종 버그 검토 (2026-09-14)

## 계기

v6.38~v6.40에 이어 같은 날 진행된 후속 작업. "상대 연결" IP 목록을 다른
목록과 같은 스타일로 통일하고, 남아있던 큰 다이얼로그 4곳을 임베드 방식으로
전환하고, 위치가 어색했던 파일 크기 설정을 옮기고, 작업표시줄 아이콘 깜빡임을
추가한 뒤, 마지막으로 오늘 작성한 코드 전체를 한 번 더 검토했다.

## 1. "상대 연결" IP 목록 스타일 통일

- `dialogs.py` `_build_static_ip_list`/`_reload_static_ip_rows`를 새로
  만들어, 단순 `tk.Listbox` 대신 "새 그룹 만들기"/"여러 명에게 한 번에
  보내기"의 상대 선택 목록(`_build_picker_list`)과 같은 아바타 원형 +
  이름/IP 2단 표시 행 스타일로 교체. 체크박스 자리에는 각 행 전용
  [삭제] 버튼을 둬서 목록에서 골라 선택할 필요 없이 그 항목만 바로 지울
  수 있게 했다.

## 2. 다이얼로그 4곳 임베드화

별도 OS 창(Toplevel) 대신 본창 안에 오버레이+패널로 뜨는 방식으로 전환.
공용 뼈대 `_make_embed_dialog(title, width, height)`를 새로 만들어(제목줄
+ ✕ 닫기 포함, `_embed_prompt_text`/`_embed_alert`보다 내용이 많은
다이얼로그용) 아래 4곳에 적용했다.

- 새 그룹 만들기 (`_group_create_dialog`)
- 상대 연결 (`_settings_dialog`)
- 여러 명에게 한 번에 보내기 (`_broadcast_dialog`) — 내부의 자동 삭제
  타이머 팝업도 이제 본창 기준 임베드라 함께 `embed=True`로 전환.
- 내 프로필 원형 클릭 시 "사진으로 프로필 등록/변경" 메뉴
  (`_open_my_avatar_menu`)

### 검증 중 있었던 일 (실제 버그 아님으로 결론)

computer-use로 화면을 캡처해 확인하던 중 패널이 안 보이는 것처럼 나와서
한동안 원인을 팠다. 격리 재현 스크립트, `winfo_ismapped()`/`winfo_geometry()`
디버그 출력, `root.update()` 강제 호출까지 시도했지만 Tk 쪽 상태는 항상
정상(`mapped=1`, 올바른 좌표/크기)이었다. 마지막으로 **앱 프로세스 안에서
직접 PIL `ImageGrab`으로 그 좌표를 캡처**해보니 다이얼로그가 완벽하게
정상 렌더링되어 있었다 — 원격 스크린샷 도구(computer-use) 쪽이 이 특정
창을 캡처하는 데서 문제가 있었을 뿐, 실제 앱에는 문제가 없었다. 디버그
코드는 모두 제거했다.

## 3. 파일 전송·다운로드 최대 크기 설정 재배치

사용자 피드백: "[상대 연결] 메뉴에 섞여 있어 안 보인다. 톱니바퀴(⚙) 설정
메뉴의 다운로드 관련 항목 쪽에 둬라."

- `_settings_dialog`에서 파일 크기 섹션을 완전히 제거하고 원래 크기(430x460)
  로 되돌림.
- 새 함수 `_max_file_size_dialog()`(`dialogs.py`)를 만들어, 대화방 헤더의
  **⚙ 설정**(`_open_room_more_menu`) 메뉴의 "📁 다운로드 폴더 열기" /
  "📂 다운로드 폴더 변경..." 바로 아래에 "📏 파일 전송·다운로드 최대
  크기..." 항목으로 추가. `_embed_prompt_text`로 숫자를 입력받아
  `Engine.set_max_file_size_mb()`(1~1024 자동 클램프)를 호출하고 결과를
  상태바에 표시.
- 참고: ⚙ 설정 메뉴는 대화방을 하나 선택해야 열리는 메뉴라(다운로드 폴더
  변경도 원래 같은 제약), 대화 미선택 상태에서는 이 설정에 접근할 수 없다.

## 4. 알림 시 작업표시줄 아이콘 깜빡임

기존에도 `Notifier.flash()`가 있었지만 `FlashWindow`(단발성 1회 반짝임)라
눈에 잘 안 띄었다.

- `winapi.py`: `FLASHWINFO` 구조체와 `FLASHW_STOP/TRAY/TIMERNOFG` 상수를
  추가하고, `flash()`를 `FlashWindowEx(FLASHW_TRAY | FLASHW_TIMERNOFG)`로
  교체 — 사용자가 창을 다시 보기 전까지 작업표시줄 아이콘이 계속
  깜빡인다. `stop_flash()`도 추가.
- `app.py`: 창이 `<FocusIn>`을 받으면 `stop_flash()`를 호출하도록 바인딩
  — 알림 클릭으로 복귀하든 Alt+Tab으로 직접 전환하든 모두 깜빡임이
  멈춘다(Windows가 포커스 시 자동으로도 멈춰주지만 안전장치로 추가).
- 알림이 뜨는 조건(포커스 아닐 때만) 자체는 기존 `_notify_if_needed`
  로직을 그대로 재사용 — 새로 손댈 필요 없었다.

## 5. 최종 버그 검토 (오늘 작성분 전체)

- **(확정, 수정) Escape로 안 닫히는 임베드 다이얼로그 3곳**: `_make_embed_dialog`가
  만든 `panel`에는 `<Escape>` 바인딩이 있지만, 이는 **panel 자신이
  포커스를 가졌을 때만** 발동한다. 다이얼로그를 열면 보통 안의 입력창
  (`name_entry`/`ip_entry`/`msg_text`)에 포커스를 주는데, 이 위젯들의
  bindtags에는 조상인 panel이 포함되지 않아 Escape가 안 먹혔다. 세 입력
  위젯 각각에 `<Escape>` → `_close()` 바인딩을 추가해 해결
  (`_group_create_dialog`의 `name_entry`, `_settings_dialog`의
  `ip_entry`, `_broadcast_dialog`의 `msg_text`).
- 그 외 나머지 코드(정적 IP 목록 렌더링의 `None`-세이프 처리,
  `_settings_win` 재사용/재생성 로직, `FLASHWINFO` 구조체 필드 순서·타입,
  FlashWindowEx 플래그 값)는 재확인 결과 문제 없음.
- `python -m py_compile` 전체 통과, `tests/test_headless.py` 회귀
  스위트 재실행 후 `ALL PASSED` 재확인.
