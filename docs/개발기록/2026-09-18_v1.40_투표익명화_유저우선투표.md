# v1.40 — 투표 익명화 + 유저 우선 투표 순서 (2026-09-18)

## 사용자 지적
"게임 진행중 이상한게, 사람들이 투표하는게 채팅창에 노출되는 구조더라고. 그리고
더 이상한게 AI 들이 나보다 먼저 투표해"

## 원인 (실측)

1. **투표 노출**: 투표 접수 시스템 메시지가 "(익명 개표)"라고 표시하면서도,
   실제로는 `🗳 {투표자} → {대상} 투표` 형태로 **누가 누구를 찍었는지 그대로
   방 전체 채팅에 방송**하고 있었다(`add_mafia_system`은 호스트 모드에서
   LAN 전체로 브로드캐스트됨). 본투표·재투표·AI투표·유저투표 전 경로가 동일한
   문제를 갖고 있었다.
2. **AI 선(先)투표**: 낮 토론 종료 20초 전, AI 전원이 채팅에 "투표 X"라고
   자동 발화하면서 그게 **곧바로 정식 투표로 반영**되고 있었다(`_ai_auto_vote`
   → `_ai_parse_and_vote`) — 정식 개표 팝업이 열리기도 전에, 유저가 아직
   고민 중인 사이 AI 표가 이미 확정되는 구조였다. 개표 팝업이 열린 뒤에도
   AI들은 0.3~1초 간격으로 백그라운드에서 즉시 투표를 던지는 반면 유저는
   직접 버튼을 눌러야 해서, 구조적으로 AI가 항상 먼저 끝났다.

## 조치

| 항목 | 내용 |
|---|---|
| 완전 익명화 | 모든 투표/재투표 시스템 메시지에서 대상 이름 제거 — `{이름}님 투표 접수 완료 (익명 개표)` 형태로 통일. 실제 표 내용은 개표 결과(`tally_votes`)에서만 공개 |
| 조기 자동투표 제거 | `_ai_auto_vote`/`_ai_parse_and_vote`(낮 토론 중 '투표 X' 자동 발화 → 즉시 반영) 완전 삭제. 실투표는 오직 개표 팝업에서만 발생 |
| 유저 우선 게이트 | `_ai_vote_user_should_wait()` 추가 — 유저가 아직 투표 전이고 팝업이 열린 지 5초가 안 지났으면 AI들의 표 반영을 0.4초 간격으로 계속 미룸. 유저가 먼저 투표하면 즉시 게이트 해제, 5초가 지나도 유저가 무응답이면 게임이 멈추지 않도록 AI가 진행 |

## 부수 발견 (같이 수정)
- 회귀 테스트차 기존 GUI 테스트를 돌리다가 **일반(비-마피아) 1:1/그룹 채팅
  전송이 아예 깨져 있던 버그**(`app.py`의 `_send()`가 텍스트를 지우기 전에
  캡처하지 않아 `UnboundLocalError`)를 발견해 같이 고쳤다 — 자세한 내용은
  `CHANGELOG.md` v6.49 참고.
- 같은 회귀 테스트에서 그룹 "가십 팬아웃" 체크가 간헐적으로 실패하는 걸
  발견했는데, 실제 로직 버그가 아니라 `tests/test_gui_flow.py`에
  `if __name__ == "__main__":` 가드가 없어 `crypto_layer.py`의
  `ProcessPoolExecutor`가 스폰될 때 테스트 스크립트 전체가 자식 프로세스로
  재실행되며 타이밍을 흔드는 하네스 아티팩트였다. 가드 추가로 해결.
