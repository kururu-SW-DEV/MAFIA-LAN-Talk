# v1.00 — 마피아 게임 최초 통합 릴리스 (2026-09-17)

## 배경

랜톡(LAN Talk) v6.48 — serverfree P2P LAN 메신저의 최신 소스를 기반으로,
같은 채팅방에서 **마피아 게임(AI 참가자 혼합)**을 진행하는 전용 배포판을
`D:\DEV\MAFIA`에 완성했다. 이전 세션(v6.24 이전 항목들)은 랜톡 본체 개발
기록이며, 이 문서부터는 마피아 게임 개발 기록(버전 1.00 시작).

## 1. 아키텍처 구축 (v1.00 이전 준비 → v1.00 포함)

| 모듈 | 역할 |
|---|---|
| `mafia_core.py` | 규칙(GameCore, Phase.DAY/NIGHT/VOTE/END, alloc_roles, cast_vote, tally_votes, enter_night, resolve_night, check_winner) |
| `mafia_ai.py` | 사내 vLLM(`http://<내부 서버 IP>`, `/v1/chat/completions`) 직접 호출(urllib), PlayerAgent, observe_all, 대화형 프롬프트 |
| `mafia_ui.py` | MafiaUIMixin — 게임방 임베딩·투표 오버레이·밤 패널·설정창·host_dm |
| `mafia_net.py` | MAFIA1 프로토콜(`hsay`/`hdm`/`asay`/`sys`/`vote`) 랜톡 UDP DM 전송 |
| `mafia_config.py` | LLM 주소·모델·AI_PERSONAS·ROLE_TABLE·타이머 상수 |
| `app_mafia_patch.py`/`_ext.py` | 랜톡 소스 교체 시 원클릭 재적용 스크립트 |

### 주요 파라미터
- MIN_PLAYERS=4, AI_PERSONAS 4인(루카·미나·레오 등), ROLE_TABLE 3~10인
- 낮 120초 / 밤 30초 / 투표 15초 카운트다운 / 개표 전 3초 긴장 지연
- AI 응답 ~2초(직접 API). hermes CLI 서브에이전트 방식은 부트 25~90초로 폐지

## 2. 이번 회차(투표·사이클 안정화)에서 고친 버그

### (1) 투표 팝업이 안 눌리고, 눌려도 계속 살아 있던 문제
- 레거시 `_popup_vote(self, result, target, win)` 정의가 새 시그니처를 덮어써
  클릭 시 TypeError → 레거시 정의 삭제
- `core.vote(dict, dict)` 등 존재하지 않는 API 호출 → `core.cast_vote(이름, 이름)` 교정
- 투표 후 버튼 잠금 로의 `unhashable type: dict` 해제
- 개표 완료 후 `open_the_vote()` 재귀(팝업이 스스로 다시 열림) 제거 →
  카운트다운 tick이 `_tally_and_reveal` 직접 호출로 변경
- 팝업 tick이 `phase != VOTE`면 즉시 취소(DAY에서 열린 팝업이 곧바로 죽음) → DAY+VOTE 허용
- 팝업 디자인을 ⚙ 설정창과 동일한 모던 스타일(카드/grid 버튼/⏳ 카운트다운)로 통일

### (2) 개표 후 다음 턴으로 안 넘어가 + AI 멈춤 (사용자 지적, 치명적)
- **원인 1**: `core.enter_night()`가 `phase != DAY`면 실패(silent return) —
  개표가 `phase=VOTE`를 세팅하는데 밤 진입이 VOTE를 거부 → 영원히 VOTE 기동
- **원인 2**: 밤 30초 카운트다운을 데몬 스레드 `time.sleep(1)` 루프로 돌리며
  `root.after(0, …)`로 컨트롤 — 메인스레드 경합으로 resolve 누락
- **수정**: `enter_night()`가 DAY+VOTE를 모두 허용 / 밤 카운트다운을
  **메인스레드 after 루프**(`_tick_night_loop`)로 전환
- 실측: `t=4s vote → t=16s night tick=21 → t=36s tick=4 → t=44s day=2`
  아침 전환 후 AI 활동 재개("루카님이 생각 중…") 확인

### (3) 투표를 하면 채팅창이 이상해보이던 것 (사용자 지적)
- 사회자가 "방이 잘못열었습니다" 식 엉뚱한 말 — LLM 응답이 캐시된 개회사
  텍스트를 재사용 → 개회사 프롬프트 명확 분리("개회 선언만")
- 마피아 밤 행동 접수가 **전체 채팅에 노출**(정보 누출 — 치명적) →
  나에게만 보이는 🔒 host_dm 개인 쪽지로 변경
- 대화 잘림 — `clean_llm_dialect`가 문단 통째로 잘랐던 것을
  **불완전한 마지막 문장(마침표 없는 꼬리)만** 제거하도록 재작성
- 게임 진행 중 [게임 시작] 버튼이 살아있던 것 → `[게임 진행 중]` 라벨 전환

### (4) "AI들이 생각 중인 걸 뱉어내는" 문제
- 원인: LLM이 reasoning을 `reasoning_content`에 담고 content를 비우며,
  fallback에서 이를 대사로 통제 없이 노출
- 수정 3단계: `_llm_call`은 content만 반환 / `clean_llm_dialect`에
  `Thinking:` 흔적 제거 / `say`에서 reasoning 흔적 검출 시 발화 생략
- 실측: 4회 연속에서 thinking 유출 0건, 응답 평균 2.1초

### (5) 부트 타이핑 표시 문구
- `⏰ OOO 님이 대화를 준비 중... (약 25초 소요)` — hermes CLI 시절 잔재(실제 4~6초) →
  `💭 OOO님이 생각 중… (약 4~6초)` 교체

### (6) 밤 대기 개선
- 밤 진입이 `mafia_config.NIGHT_SOLVE_SECONDS` import bind 값(30s)을 고정 읽어
  runtime 설정이 무시됨 → `getattr(_cfg, ...)`으로 runtime 반영
- 밤 15/10/5초 남을 때 채팅 공지("🌙 밤 N초 남았습니다") 신설

## 3. AI 특징

- **호스트 권한**: [게임 시작]을 누른 PC가 사회자(AI 포함 LLM 대표 호출) 담당
- **P2P 동기화**: 사람 참가자는 MAFIA1 텍스트 프로토콜로 게임 이벤트 수신 —
  hdm(🔒 직업 통보), hsay(사회자 발언), asay(AI 말 중계) 루oop 실험 수신 확인
- **역할 통보**: 사람은 host_dm 쪽지, AI는 sys_prompt(`역할: {self.role}`)
- **대화형**: "지들 할 말만 하는" 이전 프롬프트 → 상대 말에 직접 대답하는 방식으로 전면 교체
- **관찰력**: `observe_all`로 모든 발언을 AI memory에 적립 — 유저 말 인용을 실측 확인
- **멘션**: 유저가 AI 이름(@이름 또는 "OOO 야")을 불렀을 때 그 AI가 즉시 반응

## 4. 배포

- `build_exe.py` → `dist\MAFIA.exe` (음 ~30.7MB), ICO_EMBED는 6.48 구조에 맞춰
  `_ICON_PNG_B64` 방식 유지
- 스모크: exe 기동 시 창 제목 "MAFIA — LAN Talk" EnumWindows로 확인
- 배포 대상: `Desktop\MAFIA\MAFIA.exe` (사용 중 복사 실패는 `taskkill /F /IM MAFIA.exe` 후 재시도)
