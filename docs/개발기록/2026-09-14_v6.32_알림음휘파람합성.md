# v6.32 — 알림음을 합성 "띵동" 소리로 교체 (2026-09-14)

## 계기

v6.30에서 알림음을 Windows 시스템 별칭(`Notification.IM`)으로 바꿨는데, 사용자가
이어서 여러 차례에 걸쳐 원하는 느낌을 구체화했다:

1. "알림음을 조용한 휘파람 소리 같은 느낌으로 바꿔줘" → 피치가 스르륵 오르내리는
   순음으로 1차 합성, 미리듣기 파일 전달.
2. "휘후 같은 느낌의 소리로 바꿔줘" → 짧게 올라가는 "휘" + 길게 흘러내리는 "후"
   2음 구조로 재합성, 미리듣기 재전달.
3. "랜톡이라고 하면 어때?"(실제 음성으로 앱 이름을 말하는 알림) 제안 → Windows
   내장 음성 합성(System.Speech, PowerShell 경유)이 필요하고 이 PC에 한국어
   음성이 없으면 "랜톡"이 영어식으로 어색하게 들릴 위험이 있음을 설명드린 뒤,
   사용자가 "휘파람 소리를 그냥 유지"하기로 결정.
4. "휘후를 띵동 하는 느낌의 휘파람소리로 바꾸는건 어때?" → 음 안에서 피치가
   미끄러지는 방식 대신, 도어벨처럼 **고정된 음 하나가 확 울렸다가 서서히
   잦아드는** 엔벌로프로 재설계, 미리듣기 재전달 후 "이거 좋다"로 최종 확정.

## 수정 (`app.py`)

Windows 시스템 알림음 별칭 대신, 표준 라이브러리(`wave`·`math`·`struct`)만으로
그 자리에서 WAV를 직접 합성하는 `_soft_whistle_wav()`를 추가했다(외부 파일·패키지
불필요, 프로세스 내 최초 1회만 계산 후 캐싱). 최종 확정된 구조는 "띵동" 도어벨
리듬 + 순음(휘파람 음색):

- **"띵"**: 1300Hz 고정음, 0.20초. 시작 0.012초 동안 0→1로 확 울렸다가
  `exp(-3.2·t/dur)`로 빠르게 잦아든다.
- 두 음 사이 0.06초의 짧은 틈.
- **"동"**: 780Hz 고정음(한 옥타브 정도 낮음), 0.55초로 더 길게. 같은 방식의
  확 울림 뒤 `exp(-2.2·t/dur)`로 더 천천히 잦아들어 여운을 남긴다.

이전 "휘~후~" 버전은 음 하나 안에서 주파수 자체가 미끄러지듯 이동했지만, 이번
버전은 각 음의 피치를 고정하고 "확 울림 → 지수 감쇠"라는 종소리/도어벨풍
엔벌로프로 리듬감을 낸다. 최대 진폭은 볼륨의 24~26% 수준으로 낮게 유지해 조용한
느낌은 그대로 유지했다. `_play_notify_sound()`는 이 WAV 바이트를
`winsound.PlaySound(data, SND_MEMORY | SND_ASYNC)`로 파일 없이 메모리에서 바로
재생한다.

## 검증

- 세 차례에 걸쳐 실제 WAV 파일로 합성해 사용자에게 직접 전달, 청취 피드백을
  받아가며 반복 조정 → 최종적으로 "띵동" 버전에서 "이거 좋다" 확인받음.
- `wave` 모듈로 재생성한 WAV의 채널·샘플레이트·길이가 의도한 값과 일치하는지
  매 단계 확인.
- `winsound.PlaySound(data, SND_MEMORY)`(블로킹 버전) 단독 호출이 예외 없이
  끝까지 실행되는 것 확인.
- 기존 회귀 스위트 3종(`test_headless.py`, `test_gui_flow.py`, `smoke_gui.py`)
  재실행, 전부 통과.
- `python -m py_compile`로 문법 확인.

**추가 수정 (같은 날, 사용자가 "왜 소리가 반영 안됐어" 보고 후)**: 처음 배포한
코드가 `winsound.PlaySound(data, SND_MEMORY | SND_ASYNC)`로 호출하고 있었는데,
CPython의 `winsound` 모듈은 `SND_MEMORY`와 `SND_ASYNC`를 같이 쓰면
`RuntimeError: Cannot play asynchronously from memory`를 던지도록 명시적으로
막아둔다. `_play_notify_sound()`의 넓은 `try/except`가 이 예외를 조용히 삼켜
매번 새 알림음 대신 예전 `root.bell()`(기본 삐) 소리로 되돌아가고 있었다 —
그래서 코드는 바뀌었지만 실제로 들리는 소리는 하나도 안 바뀐 것처럼 느껴졌던
것. GUI 스레드를 막지 않으면서도 이 제약을 피하기 위해, 재생 자체를 짧은
데몬 스레드에서 동기(`SND_MEMORY`만, `SND_ASYNC` 없이) 호출로 수행하도록
고쳤다. 정확히 프로덕션과 같은 방식(스레드 + `SND_MEMORY`)으로 직접 재현해
예외 없이 재생되는 것을 확인한 뒤 회귀 스위트 3종을 다시 통과시켰다.

## 의도적으로 하지 않은 것

- 실제 음성으로 "랜톡"을 말하는 TTS 알림은 구현하지 않았다 — 한국어 음성 미설치
  PC에서 어색하게 들릴 위험과 PowerShell 서브프로세스 호출 오버헤드를 설명드린 뒤
  사용자가 보류를 선택함. 필요해지면 최초 1회만 PowerShell(System.Speech)로
  음성을 WAV로 합성해 캐싱해두는 방식으로 확장 가능하다.
- 이어서 "고양이 야옹 소리로 할 수 있니?"라는 요청도 있었다. 배음 2개 +
  비브라토를 더한 스타일화된 "야옹" 톤을 `_meow_wav()`로 합성해 미리듣기를
  전달했으나, 사용자가 "이상하다. 지금꺼 유지해"로 반려 — 순음 합성으로는
  실제 고양이 울음의 콧소리·불규칙한 떨림을 설득력 있게 재현하기 어렵다는
  한계를 확인한 셈이라, `_meow_wav()`는 코드에서 완전히 제거하고 "띵동" 버전을
  그대로 유지했다.
