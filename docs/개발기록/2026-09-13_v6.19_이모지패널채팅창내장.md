# v6.19 — 이모지/스티커 패널을 별도 팝업 대신 채팅창에 내장 (2026-09-13)

## 계기

v6.18에서 이모지·스티커 그리드 색상/간격/정렬을 여러 차례 고쳤지만, 사용자가 다시
스크린샷을 보내며 "이제는 우측에 쏠려 있어"라고 지적했다. 원인은 v6.18의 그리드
가운데 정렬 수정 자체가 아니라, `EmojiPicker`가 여전히 `tk.Toplevel` 팝업이라
**메신저 본창과 별개의 창으로 화면 위 임의의 위치에 떠 있다는 구조 자체**에 있었다.
탭 바를 균등폭으로 펼치면서 팝업의 자연폭이 넓어졌는데, 팝업 자체의 화면상 x좌표는
여전히 "이모지 버튼 위치" 기준으로 계산되고 있어(app.py의 `_toggle_emoji_picker`),
넓어진 팝업 폭만큼 버튼 기준 좌측 정렬 위치가 상대적으로 오른쪽으로 치우쳐 보이게
된 것 — 즉 그리드 안쪽 정렬을 고칠 때마다 팝업 자체의 화면 위치 계산과 자꾸 엇박자가
나는 상황이었다.

사용자가 직접 "이모티콘 선택창은 그냥 채팅창 안에 넣으면 안되니?"라고 제안했고,
이 근본적인 해결책이 맞다고 판단해 채택했다 — 팝업의 화면 좌표를 계산하는 방식
자체를 없애면, 좌우로 쏠리거나 창 밖으로 나가는 문제가 애초에 발생할 수 없는
구조가 된다.

## 구현

- **`widgets.py`**: `class EmojiPicker(tk.Toplevel)` → `class EmojiPicker(tk.Frame)`로
  전환. `wm_overrideredirect`, `withdraw`/`deiconify`, `geometry()`, 화면 좌표 기준
  "메신저 창 아래로 안 나가게" clamp 로직(v6.18에서 추가했던 것), "바깥 클릭하면 닫기"
  바인딩(`_on_outside_click`/`_arm_outside_click`)을 전부 제거했다 — 전부 "화면 위
  어딘가에 떠 있는 팝업"이었기 때문에 필요했던 코드였고, 채팅창에 내장되는 순간
  전부 불필요해진다.
  - `show()`/`hide()`는 `self.pack(fill="x", side="top", pady=(0, 4),
    before=self._before)` / `self.pack_forget()`으로 단순화했다. `before`는 생성자에서
    받은, "이 위젯 바로 위에 뜬다"의 기준이 되는 위젯(입력창 Canvas) 참조다 —
    `reply_banner`(답장 배너)·`sticker_suggest`(스티커 자동 추천 줄)가 이미 같은
    방식(`pack(before=self.input_bar)`)으로 입력창 위에 붙는 배너였으므로, 그 기존
    패턴을 그대로 따랐다.
  - `fill="x"`를 준 이유: 패널이 자기 내용물(탭 8개)이 원하는 자연스러운 폭을 고집하게
    두면, 채팅 영역이 사이드바 때문에 좁아진 상황(예: 창 폭 450px일 때 채팅 영역은
    270px 안팎)에서 패널이 그 폭보다 넓게 그려져 옆(사이드바 쪽)으로 삐져나오거나
    탭 글자끼리 겹쳐 보이는 문제가 있었다(첫 시도에서 실제로 발생 — 아래 검증 참고).
    `fill="x"`로 항상 입력창과 정확히 같은 폭에 맞추면 이 문제가 원천적으로 없어진다.
- **탭 라벨을 한글 전체 이름 → 아이콘 한 글자로 교체**: `fill="x"`만으로는 부족했다 —
  "활동/사물" 같은 긴 한글 탭 8개가 필요로 하는 폭(약 430px)이 좁은 채팅 영역보다
  커서, `fill="x"`로 강제로 욱여넣으면 이번엔 그 안의 grid 컬럼들이 자기 최소 폭보다
  더 좁게 눌려 글자끼리 겹쳐 보이는 새 문제가 생겼다. 실제 카카오톡 등 대부분의
  메신저도 탭을 텍스트가 아니라 아이콘으로 표시한다는 점에 착안해, `_TAB_ICONS` 매핑
  (최근🕒·스티커🎨·스마일리😀·제스처👍·하트❤️·동물🐶·음식🍔·활동/사물⚽)으로 탭
  글자 수 자체를 줄였다. 탭 판별 로직(`name == "최근"` 등)은 내부 데이터 그대로
  유지하고 화면에 그리는 텍스트만 아이콘으로 바꿨다.
- **`app.py`**: `self._emoji_picker = EmojiPicker(self.root, ...)` → 입력 바를 담는
  `row` Frame의 자식으로 변경하고, `before=self.input_bar`를 함께 전달하도록 생성자
  시그니처를 `EmojiPicker(master, before, on_select=..., ...)`로 바꿨다.
  `_toggle_emoji_picker()`는 좌표 계산(`emoji_btn.winfo_rootx()/rooty()`, `-220`
  매직 넘버)을 전부 지우고 `self._emoji_picker.show()`/`.hide()` 호출만 남겼다.
  대화방을 전환하거나(`_select`) 대화를 숨기거나(`_hide_conversation`, 그룹 나가기·
  기록삭제 다이얼로그) 이모지 버튼이 비활성화되는 모든 지점에 `self._emoji_picker.hide()`
  를 추가해, 패널이 열린 채로 다른 대화로 넘어가 내용이 안 맞는 상태로 남아있지
  않게 했다(reply_banner·sticker_suggest가 같은 지점에서 이미 하던 처리와 동일).

## 검증

- 헤드리스로 실제 `App` 인스턴스를 생성(withdraw된 루트 — 기존 `smoke_gui.py`와 같은
  안전한 패턴)해, 가짜 DM 대화를 하나 선택한 뒤 `_toggle_emoji_picker()`를 호출해
  (1) 패널이 처음엔 안 보이는 상태로 시작하는지, (2) 토글하면 `is_visible()`이
  True가 되고 `winfo_manager()`가 `"pack"`인지, (3) `row.pack_slaves()` 순서상 패널이
  입력창(`input_bar`)보다 앞에 오는지(= 입력창 위에 뜨는지), (4) 다시 토글하면 완전히
  사라지는지(`pack_forget` 됨), (5) 패널이 열린 상태에서 대화를 다시 선택(`_select`)
  하면 자동으로 닫히는지까지 5가지를 확인 — 전항목 통과.
- 실제 화면 검증: `App`을 (withdraw 없이) 진짜 보이는 창으로 띄우고 — 이 앱의
  메인 루트(`tk.Tk()`)를 보이는 채로 여는 것 자체는 이 세션에서 문제없이 동작한다
  (멈추는 건 어디까지나 `tk.Toplevel`을 `deiconify()`할 때뿐이며, 팝업을 없앤
  지금은 그 위험도 자체가 사라졌다) — 대화를 선택하고 이모지 버튼을 눌러 패널을
  띄운 뒤 `PIL.ImageGrab`으로 스크린샷을 찍어 확인했다. **첫 스크린샷에서 실제로
  패널이 사이드바 쪽으로 삐져나오고 탭 글자가 겹쳐 보이는 문제를 발견**해(탭 폭
  430px가 채팅 영역 270px보다 넓었던 것이 원인), 위 "탭 라벨 아이콘화"를 추가로
  적용한 뒤 재검증 — 스티커 탭·스마일리 탭 둘 다 채팅 영역 안에 완전히 들어오고
  탭 8개가 겹침 없이 한 줄에 표시되는 것을 확인했다.
- 기존 회귀 스위트 3종(`test_headless.py`, `smoke_gui.py`, `test_gui_flow.py`) 재실행,
  전부 통과. 검증 과정에서 생성된 임시 데이터 폴더와 `__pycache__`는 정리했다.

## 부수 효과 (좋아진 점)

- "바깥을 클릭하면 닫힘" 로직이 없어진 대신, 패널은 이제 이모지 버튼을 다시 누르거나
  스티커를 클릭하거나(자동 전송+닫힘, 기존과 동일) 대화를 전환할 때만 닫힌다 —
  채팅 목록을 스크롤하다가 실수로 패널이 닫히는 일이 없어졌다(내장형 UI에 더 자연스러운
  동작이라고 판단).
- Windows 고DPI 스케일링, 화면 밖 좌표, "메신저 창 아래로 안 나가게" clamp 등 v6.18에서
  씨름했던 Toplevel 특유의 화면 좌표 문제들이 전부 코드에서 사라졌다 — 채팅창 레이아웃
  안에 있는 이상 항상 메신저 창 안에서만 존재한다.
