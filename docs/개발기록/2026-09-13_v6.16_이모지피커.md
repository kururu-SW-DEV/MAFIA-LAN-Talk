# v6.16 — 이모지 피커 (2026-09-13)

- **계기**: 사용자가 "이모지와 이모티콘 기능 넣어줘 카톡같이"라고 요청. "이모지"(표준
  유니코드 문자)와 "이모티콘"(카카오톡에서 구매/다운로드하는 캐릭터 스티커 이미지)은
  전혀 다른 것이라, 먼저 범위를 확인했다 — 이모티콘 쪽은 저작권 있는 캐릭터 그림이라
  그대로 만들 수 없고, 대안으로 간단한 자체 도형 스티커를 만드는 방법도 제시했으나
  사용자가 **"이모지 피커만 먼저 구현해줘"**로 범위를 확정했다.
- **위젯 (`widgets.py`)**: `EmojiPicker(tk.Toplevel)` 신설 — `MentionPopup`과 같은
  overrideredirect 팝업 패턴을 따르되, 위쪽에 카테고리 탭(스마일리/제스처/하트/동물/음식/
  활동·사물 + "최근"), 아래쪽에 `MinimalScrollbar`가 붙은 스크롤 그리드로 구성했다.
  `EMOJI_CATEGORIES`에 카테고리별 유니코드 이모지 목록(총 150개 이상)을 직접 나열했다.
  이모지를 클릭해도 팝업이 안 닫히게 해서(카카오톡처럼) 여러 개를 연달아 고를 수 있다.
  바깥 클릭으로 닫히는 로직은 기존 `_popup_menu`(dialogs.py)의 "여는 순간 자기 자신을
  닫아버리는" 문제를 회피하려고 한 틱 미뤄서 바인딩을 등록하는 패턴을 그대로 재사용했다.
- **최근 사용 이모지 (`engine.py`)**: `get_recent_emoji()`/`add_recent_emoji()`를
  신설 — 이미 있던 `_update_settings()` 패턴을 그대로 써서 `settings.json`에
  `"recent_emoji"` 키로 영속화(최대 24개, 중복 선택 시 맨 앞으로 재정렬, 새 항목이
  오면 뒤에서 밀려남). 네트워크 전송이 필요 없는 순수 로컬 UI 편의 기능이라 프로토콜
  변경은 전혀 없었다.
- **연동 (`app.py`)**: 입력 바에 `😊` 버튼 추가(첨부/폭파 타이머 버튼 오른쪽,
  `_layout_input_bar`에 너비 계산 추가). 클릭하면 `EmojiPicker.show()`, 이모지를
  고르면 `self.entry.insert("insert", ch)`로 커서 위치에 삽입하고 `add_recent_emoji()`
  호출. 다른 대화방 미선택 시 비활성화되는 기존 4곳의 UI 초기화 블록(생성자, 대화
  숨기기, 그룹 나가기, 대화 기록 삭제)에도 `emoji_btn` 비활성화를 추가해 `burn_btn`과
  동일하게 다뤘다.
- **검증**: (1) 엔진 — 최근 사용 목록이 최신순으로 쌓이는지, 중복 선택 시 재정렬되는지,
  24개로 개수가 제한되는지 확인. (2) App — 대화 선택 시 버튼 활성화, 이모지 선택 시
  입력창 커서 위치에 정확히 삽입되고 엔진의 최근 목록에도 등록되는지 확인. (3)
  `EmojiPicker` 위젯 — 실제 화면에 띄우는 `.show()`(내부적으로 `deiconify()`를 호출)는
  이 자동화 세션에서 여러 차례 재현된 환경 한계(Toplevel을 실제로 화면에 매핑하려는
  시점에 멈추는 문제, v6.9/v6.15에서도 같은 사유로 우회한 바 있음)를 다시 마주칠 걸로
  보고 애초에 호출하지 않았다 — 대신 `_switch_cat()`/`_pick()` 등 내부 로직을 직접
  호출해서 카테고리 7개 전부가 예외 없이 그리드를 그리는지, 선택 시 콜백이 실제로
  실행되는지를 확인했다. 기존 회귀 스위트 3종도 재실행해 전부 통과.
- **의도적으로 범위에서 뺀 것**: 카카오톡 "이모티콘"(캐릭터 스티커) — 저작권 문제로
  실제 캐릭터 그림은 만들 수 없고, 사용자가 우선 이모지만 먼저 요청했다. 필요하면
  나중에 간단한 자체 도형(원형 스티커 등)으로 별도 논의 가능.
