# v5.4 set_alias 데드락 해결, 대화 미리보기 O(1) 메모리 캐시 & local_ips TTL 캐싱 (2026-09-11)

- **`set_alias()` 데드락(UI 멈춤) 근본 해결**:
  - 버그 원인: `set_alias()` 내부에서 `with self.settings_lock:`을 잡은 채 `self._save_aliases()`를 호출했고, `_save_aliases()`가 다시 `self._update_settings()`를 통해 같은 락을 획득하려다 단일 락 재진입 데드락이 발생하여 Tkinter 메인 스레드가 정지되던 문제.
  - 조치:
    1) `set_alias()`에서 `self.aliases` 딕셔너리 수정만 락으로 감싸고, `self._save_aliases()` 호출을 락 밖으로 이동하여 `hide_key`/`unhide_key`와 동일한 안전한 단일 책임 패턴으로 통일.
    2) `self.settings_lock`을 `threading.RLock()`으로 견고하게 유지하여 향후 어떤 경로에서도 재진입 데드락이 발생하지 않도록 방어.
- **대화 미리보기(`_preview`, `_preview_group`) O(1) 메모리 캐시 구축**:
  - 성능 문제: 검색창 타이핑(`_ph_changed`), 3초 주기 온라인 상대 presence 수신, 메시지/파일 송수신, 탭 전환 시마다 목록의 모든 대화에 대해 디스크의 전체 JSONL 로그를 처음부터 끝까지 읽고 파싱(`load_history`/`load_group_history`)하여 CPU/디스크 I/O 병목이 발생하던 문제.
  - 개선:
    1) `Engine`에 `_last_record_cache` 메모리 딕셔너리를 신설하고, 메시지/파일 로그 append 시점에 O(1)로 실시간 갱신.
    2) `Engine.get_last_history_record(key)`를 추가하여 `_preview`/`_preview_group`이 메모리 캐시만 즉각 읽도록 변경 (디스크 I/O 제로화).
    3) 앱 최초 실행 또는 캐시 미스 시에도 전체 파일을 읽지 않고, 파일의 끝부분(8KB)만 역방향으로 탐색하여 마지막 1줄만 빠르게 파싱(`_read_last_record_from_file`)하도록 최적화.
- **창 크기 조절/스플리터 드래그 시 활성 대화방 메모리 캐시 재활용 (`_reload_chat`)**:
  - 개선: 창 크기 조절이나 스플리터 드래그로 인한 대화창 리사이즈 시(`_resize_apply`), 디스크에서 다시 로그를 읽지 않고 현재 열려 있는 대화방의 파싱된 레코드(`self._active_chat_records`)를 재사용하여 즉시 화면을 렌더링.
- **`local_ips()` 30초 TTL 캐싱 및 `_is_self()` 고속화**:
  - 성능 문제: 패킷 수신 및 멤버 검사마다 `local_ips()`가 호출되어 매번 소켓 생성, connect(255.255.255.255), close, gethostbyname_ex DNS 시스템 콜이 반복되던 부하.
  - 개선:
    1) `local_ips()`에 30초 TTL 메모리 캐시(`_LOCAL_IPS_CACHE`)를 적용하여 불필요한 시스템 콜 차단.
    2) `Engine.__init__`에서 `self._my_ips = set(local_ips())`를 캐시하고, `_is_self()`에서 메모리 Set 비교로 즉각 판정하여 1,000회 연속 검사도 1ms 미만으로 고속 처리.
