# v1.06 — 재투표 접수·개표 멈춤 해소 + 사회자-AI 이름 일치 (2026-09-18)

## 사용자 지적
"재투표 접수시에 개표중으로 멈춰있어"
"사회자가 지칭하는 참가자와, 실제 AI들의 이름이 달라"

## 원인 (실측 확정)

1. **AI 재투표 접수 코드가 아예 없었음** — 1차 개표 동률 → 재투표 팝업이 열려도
   AI 표가 접수 안 되므로 `all(votes 체크)`가 영원히 False → "개표중" 정지.
2. **유저 무응답 safety net 부재** — 유저가 재투표 팝업을 30초 이상 안 누르면
   개표가 영원히 대기.
3. **1차 표가 재투표 풀에 남아 있음** — 재투표는 동률 후보만으로 다시 수집해야
   하는데 1차 표가 그대로 남아 2차 개표가 잘못 집계될 수 있었음.
4. **사회자 지칭 이름 불일치** — `spawn_all`이 인격 템플릿의 기본 이름으로
   PlayerAgent.name을 만들어 사회자/AI가 실제 접수된 AI 명단과 다른 이름을 말하는
   원인(인격 'name'은 톤 템플릿 뿐이어야 함).

## 조치

| 항목 | 내용 |
|---|---|
| AI 재투표 | `_ai_revote_fast(tied, pl)` 신설 — 동률 후보 중에서 즉시 결정(350ms 간격). |
| 유저 무응답 | `_force_revote_tally` 신설 — 30초 후 미투자 전원 기권 처리 + 강제 개표. |

| 개표 체크 | `_check_revote_done` — 전원 접수되는 즉시 after(700) 2차 개표, 타이머 정리. |
| 이름 일치 | `AIDirector.spawn_all(..., names=core AI 실명)` — 실측 core.players=['정민호','김과장','지은','현우'] / ai.players=['김과장','지은','현우'] matches True. |

## 실측 (재투표 전 경로)

```
1차 동률: 정민호 2표 vs 김과장 2표 → "동률 후보만으로 1회 재투표!"  [tied=['김과장','정민호']]
t+2 votes: {정민호2, 김과장1} → 유저 '김과장' 재투표 클릭
t+8 votes: 김과장→정민호, 지은→김과장, 현우→정민호, 정민호→김과장  →  정민호2 : 김과장2 (재동률)
재투표도 동률 → "처형 무효, 밤으로" → phase=night
50초 관찰: final phase=day, day_no=2 — 낮 2로 정상 복귀.
```

## v1.06 후속 — 사회자-AI 이름 불일치 진원지 확정 (2026-09-18)

호출부에서 `spawn_all(personas, host, players_desc)`에 `names=` 인자를 넘기지 않아
PlayerAgent.name이 인격 템플릿 기본 이름으로 생성되고 있었다(사회자/시스템 안내문은
core.players 실명 기반 → 둘이 어긋남).

조치:
- mafia_ui: `ok = self.ai.spawn_all(..., names=[AI 실명])`로 교정.
- 개회사 프롬프트에 "명단에 없는 이름 환각 금지 — 있는 이름만" 문구 추가.
- mafia_ai: `sanitize_player_names` 신설 — 사회자 응답 중 'OOO님' 언급을
  실참가자 명단과 유사매칭, 명단 밖이면 제거(+빈 문장 시 기본문 대체).
