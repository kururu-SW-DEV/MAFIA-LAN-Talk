# v6.22 — 외부 코드 리뷰 보고서 검증 및 확정 결함 수정 (2026-09-13)

## 계기

사용자가 "① 버그 및 잠재 결함, ② 고아 코드, ③ 중복 코드, ④ 최적화 포인트" 4개
영역으로 정리된 코드베이스 정밀 분석 보고서를 그대로 전달했다. 보고서 내용을
곧이곧대로 반영하는 대신, 각 항목을 실제 코드에서 하나씩 재현·대조해 **진짜
결함만** 고쳤다 — 외부 보고서는 근거 없이 신뢰하면 안 되고(특히 "미사용"·"버그"
판정은 실제로 grep/read로 호출부까지 추적해야 확실함), 실제로 검증해보니 보고서의
일부 항목은 사실과 달랐다.

## 확정 수정 내역

### 버그

- **① 디바운스 딕셔너리 동시성**: `_avatar_req_debounce`/`_clock_skew_debounce`를
  수신 스레드(`_recv_loop`/`_handle`)가 값을 쓰고, 하트비트 스레드(`_presence_loop`
  → `_prune`)가 `[k for k, ts in d.items()]`로 순회하며 만료 항목을 지우는데, 둘
  사이에 락이 전혀 없었다. 순회 도중 다른 스레드가 키를 넣으면
  `RuntimeError: dictionary changed size during iteration`로 하트비트 스레드가
  죽고, 그러면 온라인 상태 브로드캐스트와 자동 폭파 청소(`_sweep_burns`)가 함께
  멎는다. `self._debounce_lock`을 새로 만들어 쓰기(`_check_fetch_avatar`,
  `_handle`의 clock_skew 로그)와 읽기/정리(`_prune`) 양쪽을 모두 이 락으로 감쌌다.
  writer 3개 + pruner 2개 스레드를 1.5초 동시 실행시켜 `RuntimeError` 없이
  통과하는 것으로 검증.
- **②/⑤ 자동 폭파·기록 삭제 시 공지(pin) 잔존**: `_sweep_one_burn_file`은 burn
  타이머로 메시지를 영구 삭제하면서도 그 메시지가 공지로 지정돼 있었는지는
  확인하지 않았고, `delete_history`도 방의 공지를 그대로 뒀다. 둘 다 삭제된
  mid가 현재 공지의 mid와 같으면(또는 기록 전체 삭제 시 공지가 있으면)
  `clear_pinned_notice(key)`를 호출하도록 고쳤다 — 안 그러면 본문은 사라졌는데
  평문 공지만 `settings.json`에 영구 잔존해, 다음에 그 방을 열면(또는 재시작하면)
  이미 없는 메시지를 가리키는 고아 공지 배너가 다시 나타난다.
- **③ 대화 목록 미리보기 — 스티커만 실제 결함**: 보고서는 "파일명 대신 발신자
  이름이 뜬다"고 주장했지만, 코드를 추적해보니 `_rec_preview_text`는 **DM 전용**
  함수이고 DM 파일 레코드는 애초에 `"name"` 필드에 파일명을 담는다
  (`_append_log_file`). 그룹 파일은 `_preview_group`이라는 별도 함수가 이미
  `"fname"`을 올바르게 쓰고 있었다 — 오탐. 다만 같은 함수들이 `kind=="sticker"`
  레코드(본문 `text`가 항상 `""`)를 처리하지 않아 대화 목록에 **빈 미리보기**로
  뜨는 건 실제 문제였다. `_rec_preview_text`와 `_preview_group` 둘 다
  `stickers.STICKERS`에서 이름을 찾아 `"[이모티콘] 이름"`으로 표시하도록 추가했다.
- **④ 통합 검색 — 스티커 검색 불가 + 발신자 이름 오탐**: 실제 결함이었다.
  `txt = r.get("text") or r.get("fname") or r.get("name") or ""` 한 줄이 파일/
  일반 텍스트/그룹 스티커를 전부 같은 방식으로 처리하다 보니, ⓐ 스티커는
  `text`가 비어 있어 이름("감사한 미소" 등)으로 검색해도 안 걸리고, ⓑ 그룹
  스티커는 `text`·`fname`이 둘 다 없어 그 폴백이 결국 발신자 `name`으로
  떨어져서, 사람 이름을 검색하면 그 사람이 보낸 스티커가 "본문에 이름이
  있는 것처럼" 오탐됐다. `kind`별로 분기해 스티커는 이름+키워드로 매칭하고
  화면엔 `"[이모티콘] 이름"`을, 파일은 `fname`(그룹)/`name`(DM)을, 일반
  텍스트는 `text`만 쓰도록 정리 — 발신자 이름을 본문으로 취급하는 경로 자체를
  없앴다. 스티커 이름 검색 시 매칭됨, 발신자 이름 검색 시 스티커 false-positive
  없음을 각각 확인.
- **⑥ 클립보드 GlobalLock 누수**: `GlobalLock(h)`가 성공(`ptr` truthy)했는데
  `size <= 40`이면 대응하는 `GlobalUnlock(h)`를 건너뛰고 있었다. `try/finally`로
  감싸 `ptr`이 있으면(=락을 실제로 잡았으면) 어떤 경로로 빠져나가든 반드시
  `GlobalUnlock`이 호출되도록 고쳤다.

### 고아 코드

- `Engine.rename_conversation()` — 호출부가 전혀 없어(UI는 `_rename_conversation_dialog`
  에서 `rename_group`/`set_alias`를 직접 호출) 제거.
- `constants.C_LINK` — URL 하이라이트는 실제로 `chat_renderer.py`가 `"#38bdf8"`을
  하드코딩해서 쓰고 있어(`C_LINK`는 애초에 안 쓰임) 제거.
- `constants.PEER_CONTENT_GAP` — 보고서는 미사용이라 했지만, 바로 다음 줄
  `PEER_BUBBLE_X = MARGIN_SIDE + PEER_AVATAR_SIZE + PEER_CONTENT_GAP` 계산에
  실제로 쓰이고 있어 **존치**(오탐).
  `winapi.WM_DROPFILES`/`GWLP_WNDPROC` — 어디서도 참조되지 않음(드래그앤드롭은
  `dnd_handler.py`가 독자적으로 같은 상수를 재정의해서 씀) — 제거.
- `app.py` 미사용 임포트 정리: `messagebox`(주석에만 언급), `wintypes`,
  `date_str`, `ensure_vendored_pil`, `local_ips`, `parse_target`, `URL_REGEX`
  제거. `ttk`는 `isinstance(w, (tk.Entry, ttk.Entry, ...))`에 실제로 쓰이고
  있어 존치(오탐).
- `backup/app.py.bak` — 파일 자체는 존재하지만 이미 전용 `backup/` 폴더에
  격리돼 있어(루트가 아님, 보고서의 위치 설명도 부정확했음) 배포에 영향이
  없고, 사용자가 의도적으로 보관 중인 이력일 수 있어 **삭제하지 않고 보류**
  — 정리를 원하시면 말씀해 주시면 됩니다.

### 중복 코드

- **대화방 UI 리셋 18줄**: `app.py`의 `_hide_conversation`, `dialogs.py`의
  `_leave_group_dialog`/`_delete_conversation_history_dialog` 세 곳에 동일한
  "현재 대화방을 화면에서 완전히 비우는" 블록이 그대로 복사돼 있었다.
  `App._clear_active_chat_view()`로 통합하고 세 호출부 모두 이 메서드 호출로
  교체 — 앞으로 버튼/배너가 하나 늘어도 한 곳만 고치면 된다.
- **MouseWheel `bind_all`/`unbind_all`**: 보고서 지적대로 `bind_all`/`unbind_all`
  은 위젯별이 아니라 앱 전체에서 공유되는 단 하나의 전역 바인딩 슬롯이라,
  이론적으로는 스크롤 컨테이너 전환 시 순서가 어긋나면 스크롤이 안 먹는 상황이
  발생할 수 있다. 다만 기존 코드에 이미 `<Destroy>` 시점 방어적 unbind가 걸려
  있고, 실제로 재현 가능한 실패 시나리오를 만들어내지 못해 — 확정 결함으로
  보기엔 근거가 부족하다고 판단해 이번엔 손대지 않았다. 여러 스크롤 가능한
  팝업을 빠르게 넘나들다 스크롤이 먹통이 되는 걸 실제로 겪으시면 알려주시면
  그때 재현 시나리오를 기준으로 고치겠다.

### 최적화

- **스티커 추천 줄 매 타자 재생성**: `_show_sticker_suggest`가 추천 목록이
  이전과 같아도 매번 기존 위젯을 destroy하고 새로 그렸다. `self._cur_suggest_sids`
  에 마지막으로 그린 목록을 기억해두고 동일하면 스킵하도록 가드 추가 — 깜빡임과
  불필요한 재작업 제거.
- **창 높이만 바뀌어도 채팅 전체 재렌더링**: 말풍선 줄바꿈/배치는 `_chat_width()`
  (가로 폭)에만 의존하는데, `<Configure>` 이벤트는 세로 크기 변경에도 그대로
  발동해 매번 `_reload_chat`을 호출하고 있었다. `_resize_apply`에 마지막 렌더
  폭(`_last_rendered_width`)을 기억해뒀다가 폭이 실제로 안 바뀌었으면 재렌더링을
  건너뛰도록 가드 추가.
- **`_last_record_cache` 락 불일치**: 읽기(`get_last_history_record`)는
  `log_lock`으로 보호하면서 쓰기(`_append_log`, `_append_log_file`,
  `_append_group_log`, `_append_group_log_file`, `load_history`,
  `load_group_history`)는 락 밖에서 갱신하고 있었다. CPython GIL 덕에 크래시
  위험은 없지만(단순 dict 대입은 원자적) 락 사용 규칙이 일관되지 않았던 것도
  사실이라, 전부 `log_lock` 안에서(가능하면 실제 파일 쓰기 성공 후에) 캐시를
  갱신하도록 통일했다 — 부수적으로 "파일 쓰기는 실패했는데 캐시만 갱신되는"
  드문 불일치도 함께 없앴다.
