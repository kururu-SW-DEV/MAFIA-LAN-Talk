# v6.8.2 타이핑 중 한글 조합 글자 확대 버그 — 진짜 근본 원인(DPI 비인식) 발견 및 수정 (2026-09-13)

- **계기**: "재미나이에게 맡겼는데 채팅창에 타이핑하면 글씨가 커지는 버그가 또 재현됐다"는
  보고. 지난 세션에 `apply_ime_font()`(IME 조합 글꼴을 위젯 글꼴과 맞추는 IMM32 호출)로
  고쳤다고 확인했던 바로 그 증상이 다시 나타났다는 것.
- **1차 확인**: `apply_ime_font` 코드 자체는 재미나이 수정본에도 그대로 남아있었고,
  `ImmGetCompositionFontW`로 실제 위젯의 IME 컨텍스트를 다시 읽어봐도 "맑은 고딕 / -16"처럼
  정상적으로 설정돼 있었다 — 즉 API 레벨에서는 이전과 똑같이 "정상"으로 보였다.
- **실제 재현**: `ImmSetCompositionStringW`로 실제 한글 조합 상태를 강제로 만들어 스크린샷을
  찍어보니, 여전히 조합 중인 글자("박")가 이미 커밋된 글자("김")보다 명백히 크게 렌더링됐다
  — API가 "정상"이라고 답하는 것과 실제 화면 렌더링이 어긋나는 상황.
- **진짜 근본 원인 발견**: 이 PC 화면이 **115 DPI(약 120% 배율)**로 설정돼 있는데, 프로그램이
  지금까지 단 한 번도 **DPI 인식(DPI-aware) 프로세스로 선언된 적이 없었다**(`SetProcessDpiAwareness`/
  `SetProcessDPIAware` 호출이 코드 전체에 전무했음을 확인). DPI-비인식 상태에서 배율이
  100%가 아닌 화면은, Windows가 앱을 "호환성 모드"로 취급해 앱이 96dpi인 줄 알고 그린 창
  전체를 사후에 비트맵으로 확대해서 보여준다. 문제는 IME 조합 팝업처럼 시스템이 별도로
  그리는 요소는 이 확대 대상이 아니라 항상 네이티브 해상도로 그려진다는 것 — 그래서
  `apply_ime_font`로 조합 글꼴 크기를 실측 DPI 기준으로 아무리 정교하게 계산해 맞춰도,
  앱 자체가 사후에 늘어나 있는 비율만큼 조합 중인 글자만 상대적으로 다르게(더 크게) 보이는
  현상은 근본적으로 없어질 수 없었다. 지난 세션 검증 때는 우연히 이 어긋남이 덜 두드러져
  보였을 뿐, 처음부터 이게 진짜 원인이었다.
- **수정**: `winapi.py`에 `ensure_dpi_awareness()`를 신설 — `SetProcessDpiAwareness(2)`
  (PROCESS_PER_MONITOR_DPI_AWARE)를 시도하고, 실패하면 `SetProcessDPIAware()`(구버전
  Windows 폴백)로 넘어간다. `lan_messenger.py`의 `main()` 맨 앞, **`tk.Tk()`로 첫 창을
  만들기 전에** 호출하도록 배치했다 — Windows는 프로세스의 DPI 인식 모드를 "첫 창이 뜨기
  전"에만 확정할 수 있어서 순서가 절대적으로 중요하다(다른 진입 스크립트에서 `tk.Tk()`를
  먼저 만들면 이 호출은 효과가 없다).
- **회귀 위험 검토**: DPI 인식으로 전환하면 Tk가 그동안 신뢰해온 "Windows가 사후에 통째로
  확대해준다"는 전제가 사라지므로, 지금까지 픽셀 단위로 튜닝해온 아바타 원·버튼·여백 등
  레이아웃 전체가 흔들릴 위험이 있었다. `winfo_fpixels("1i")`로 Tk가 실제로 115dpi를
  인식하는지 확인한 뒤, 전체 창 스크린샷(사이드바·아바타·버튼)과 아바타 원 확대 스크린샷을
  따로 찍어 앤티앨리어싱·비율이 그대로인지 확인 — 이 화면(115dpi)에서는 레이아웃 붕괴 없이
  깨끗하게 유지되는 것을 확인했다.
- 검증: 수정 전/후 모두 `ImmSetCompositionStringW`로 실제 조합 상태를 재현해 스크린샷
  비교 — 수정 후 "김"과 조합 중인 "박"의 글자 크기가 완전히 일치하는 것을 확대 스크린샷으로
  확인. `python -m py_compile` + 3종 무인 테스트도 재통과(테스트 스크립트들은 `tk.Tk()`를
  직접 만들어 쓰므로 `ensure_dpi_awareness()` 경로와 무관 — 실행 결과에 영향 없음을 함께 확인).
