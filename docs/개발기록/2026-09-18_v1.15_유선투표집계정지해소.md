# v1.15 — 유저 선(先)투표 시 AI 표 유실 → 집계 정지 해소 (2026-09-18)

## 사용자 지적
"이번에는 투표를 해도 집계가 안끝나서 진행이 안되네"

## 원인 (실측 확정) — 3중

1. **진원지: `_ai_vote_in_popup` 첫 줄**
   `if not getattr(self, "_vote_btns", None): return`
   유저가 AI보다 **먼저 투표**하면 v1.10 overlay 즉시 닫기가 `_vote_btns={}`로
   비우고, 그 뒤에 예약된 AI 표 접수(root.after)들이 전부 이 return으로
   **유실**됨 → all_voted 영원히 False → 집계 정지.
2. AI가 all_voted를 만족시켜도 개표 트리거 부재 — `_vote_remaining=1`만
   바꾼 뒤 tick이 이미 취소된 상태여서 재개표가 영원히 오지 않음.
3. AI 표 접수 대기 시작이 1.5초 — 유저 대기 체감 악화.

## 조치 (v1.15)

| 항목 | 내용 |
|---|---|
| 유실 방지 | `_ai_vote_in_popup`가 팝업 닫힘 후에도 표 접수 지속(mafia_active/phase/중복표 가드) |
| 즉시 개표 | AI 접수로 all_voted True 되는 순간 `_cancel_vote_popup` + `after(300, _tally_and_reveal)` 조기개표 |
| 접수 단축 | 첫 AI 300ms, 이후 350ms 간격(기존 1.5초 → 대기 단축) |
| 안전망 | `_popup_vote`에서 표 누락 시 `_silent_tally_if_pending` 15.5초 강제 개표 유지 |
| 위젯 방어 | `_update_vote_btn_state`가 닫힌 위젯 접근 시 TclError 무시 |
