# v6.13 — 7대 핵심 결함 정밀 수정 및 무결성 강화 (2026-09-13)

### 1. `read_ack` / `gread_ack` 지연 플러시 동기화 및 실시간 화면 미반영 수정 (`engine.py`, `app.py`)
- **결함 원인**: v6.9에서 디스크 I/O 최적화를 위해 도입된 `_mark_read_in_log` 및 `_mark_group_read_in_log`의 300ms 디바운스 타이머(`_flush_read_ack`, `_flush_gread_ack`)로 인해, 네트워크 수신 즉시(0ms) 발생한 `read_ack` 이벤트를 GUI가 받았을 때는 디스크에 여전히 `unread: True` 상태였음. 300ms 후 실제 디스크 쓰기가 완료되었을 때는 아무런 이벤트가 방출되지 않아 보낸 사람의 화면에서 '1' 배지가 실시간으로 사라지지 않고 방을 나갔다 와야만 갱신되던 결함.
- **해결책**:
  - `engine.py`의 `_flush_read_ack` 및 `_flush_gread_ack`에서 실제 디스크 파일 업데이트(`updated == True`) 완료 시점에 `self._emit({"ev": "read_ack", "peer": (ip, port), "flush": True})` 및 `self._emit({"ev": "gread_ack", "gid": gid, "flush": True})`를 방출.
  - `app.py`의 `_pump()`에서 이벤트 수신 시 `self._reload_chat(self.current, from_cache=False)`를 호출하여 변경된 최신 디스크 파일 내용을 즉시 화면에 반영함으로써 읽음 배지 해제와 자동 폭파 카운트다운 시작이 실시간으로 동기화되도록 수정.

### 2. 연속 발신 시 자동 폭파 배지(`🔥30초`) 및 읽음 배지 누락 결함 수정 (`app.py`)
- **결함 원인**: `_draw_record`의 5분 이내 연속 발신 말풍선 스택 로직(`is_same_group`)이 활성화되면 `_draw_label` 호출을 통째로 생략함. 이로 인해 동일 발신자가 연달아 보낸 두 번째 메시지에 자동 폭파(`burn_sec`)가 걸려 있더라도 상단 `🔥` 배지와 시간/읽음 표시가 완전히 누락되어 사용자가 폭파 메시지임을 인지하지 못하던 치명적 UX 결함.
- **해결책**:
  - `is_same_group` 판정 조건에 `not burn_sec and not last_burn and (not mine or has_unread == last_unread)`를 추가.
  - 자동 폭파 타이머가 걸린 비밀 메시지는 독립된 그룹으로 취급하여 `🔥` 타이머 라벨을 필수 렌더링하고, 폭파되지 않는 일반 메시지와 한 묶음으로 섞이지 않도록 격리.
  - 읽음 상태가 변경된 연속 발신 메시지도 읽음 배지가 누락되지 않도록 상태 추적 변수(`_last_burn_sec`, `_last_has_unread`)를 도입해 교정.

### 3. `_flush_outbox` 비동기 전송 도중 신규 메시지 전송 시 Outbox 메시지 영구 유실(Race Condition) 방어 (`engine.py`)
- **결함 원인**: 상대방 접속 시 아웃박스 대기열을 비우는 `_flush_outbox`의 `worker` 스레드가 수 초간 네트워크 전송을 수행하는 도중 메인 스레드에서 새 메시지가 `_enqueue_outbox`로 들어왔을 때, `worker` 종료 시점에 `self.outbox[target_k] = remaining` 또는 `self.outbox.pop(target_k, None)`을 실행하여 새로 들어온 메시지까지 함께 덮어쓰거나 영구 삭제해버리던 경쟁 상태(Race Condition) 결함.
- **해결책**:
  - `worker` 스레드에서 전송에 성공한 메시지 ID(`sent_ids`)를 수집한 후, 락(`outbox_lock`) 내부에서 최신 대기열(`self.outbox.get(target_k, [])`)을 조회하여 성공한 메시지만 필터링(`it.get("pkt", {}).get("id") not in sent_ids`)하도록 수정.
  - 전송 작업 도중 유입된 새 메시지가 절대 유실되지 않고 안전하게 보존되도록 보장.

### 4. 그룹 메시지 전송 후 하단 상태표시줄 "전송 중…" 영구 고착 버그 해결 (`app.py`)
- **결함 원인**: 메시지 입력 후 전송 시 상태바가 `"전송 중…"`으로 설정되는데, 1:1 대화(`_on_sent`)와 달리 그룹 대화 콜백인 `_on_gsent`에서는 `if ev.get("ok"): return`으로 조기 리턴해버려 전송이 성공했음에도 상태바 텍스트가 영구적으로 `"전송 중…"`에 머물러 있던 결함.
- **해결책**: `_on_gsent`에서 `ev.get("ok")`가 `True`일 때 `self.status.set("전송 완료")`를 호출한 후 리턴하도록 수정.

### 5. `Engine.list_categories()` 동시성 락 누락 및 RuntimeError 방어 (`engine.py`)
- **결함 원인**: `set_category`와 `get_category`는 `settings_lock`으로 동시성을 보호하고 있었으나, `list_categories`만 락 없이 `self.contact_categories.values()`를 순회하여 백그라운드 카테고리 갱신과 UI 조회가 겹칠 때 `RuntimeError: dictionary changed size during iteration`이 발생할 수 있던 잠재 위험.
- **해결책**: `list_categories` 메서드 전체를 `with self.settings_lock:`으로 감싸 스레드 안전성 보장.

### 6. 그룹 이벤트 방출 시 `gid` 누락으로 인한 열려 있는 대화창 미갱신 수정 (`engine.py`)
- **결함 원인**: `app.py`는 `if ev.get("gid") == cur[1]: self._reload_chat(cur)`로 현재 보고 있는 그룹방의 이벤트만 선별 갱신하도록 되어 있었으나, `engine.py`의 `create_group`, `add_group_members`, `rename_group`, `group_invite` 수신부에서 `self._emit({"ev": "group"})` 호출 시 `gid`를 전달하지 않아 방 이름 변경이나 멤버 초대가 발생해도 현재 화면이 자동으로 새로고침되지 않던 결함.
- **해결책**: 관련 4개 위치의 `_emit` 호출에 모두 `"gid": gid`를 명시적으로 포함하여 GUI가 현재 보고 있는 방을 즉시 식별하고 실시간 갱신할 수 있도록 수정.

### 7. 대화 기록 삭제(`delete_history`) 시 실시간 캔버스 초기화 누락 해결 (`app.py`)
- **결함 원인**: 엔진에서 대화 기록 삭제 시 `{"ev": "history_deleted", "key": key}`를 발행하지만, GUI의 `_pump()` 루프에 해당 이벤트를 수신하는 핸들러가 누락되어 있어 우클릭으로 '대화 내용 삭제'를 실행해도 현재 열려 있는 대화창의 메시지들이 즉시 사라지지 않던 결함.
- **해결책**: `_pump()`에 `elif kind == "history_deleted":` 분기를 추가하여 현재 열려 있는 대화방인 경우 `self._reload_chat(self.current, from_cache=False)`를 즉시 호출, 캔버스를 깨끗하게 초기화하도록 연동.
