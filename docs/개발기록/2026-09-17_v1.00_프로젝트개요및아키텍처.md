# 프로젝트 개요 — 목적·제약·아키텍처·개발 경위·검증·한계 (2026-09-17)

> 기반으로 마피아 게임 기능을 얹은 전용 배포판의 "왜 이렇게 만들었는가",

## 1. 요구와 해법

| 항목 | 내용 |
|---|---|
| 요구 | 랜톡(LAN Talk) 채팅 UI 안에서 돌아가는 마피아 게임. 참가자는 사람(AI 없음 버전도 가능) + AI 에이전트 혼합 |
| 기반 | 랜톡 v6.48 소스(`LAN-Talk-serverfree-P2P-LAN-messenger-6.48.zip`)를 원본으로 사용. 원본 압축본은 v1.62부터 저장소에서 제외(로컬 `docs/`에만 보관) — 원본 저장소: https://github.com/kururu-SW-DEV/LAN-Talk-serverfree-P2P-LAN-messenger |
| 방식 | 마피아 로직은 **별도 모듈(mafia_*.py) 추가 + app.py는 패치 스크립트로 재적용** — 랜톡 소스를 갈아끼운 뒤에도 `app_mafia_patch.py`(86행)·`app_mafia_patch_ext.py`(98행) 원클릭 재적용 |
| AI | 사내 vLLM(OpenAI 호환 `/v1/chat/completions`)을 **urllib 직접 호출**. hermes CLI 서브에이전트 방식은 부트 25~90초 지연으로 폐지(사용자 지시: "헤르메스에서 부르는게 아니야") |

```

mafia_ui.py               UI — MafiaUIMixin: 게임방 임베딩, 투표 오버레이(15s 카운트다운),

                          (hsay 공개/hdm 직접 PM/asay AI 말 중계/sys 개표·밤낮/vote 투표)
mafia_config.py           상수 — LLM 서버·모델, AI_PERSONAS 4인, ROLE_TABLE(3~10),
                          NIGHT_SOLVE_SECONDS=30, VOTE_WINDOW=15, VOTE_REVEAL_DELAY=3
app_mafia_patch.py / _ext.py   app.py 재적용 스크립트(랜톡 소스 교체 시 원클릭)

```

- **LLM엔진** vLLM 서버에서 Qwen3-27B 식 모델(`Qwen/Qwen3-27B`) 사용. system prompt에 `/no_thinking` 지시로 reasoning_content 유출 방지.
- **호스트 권한**: [게임 시작]을 누른 사람 = 사회자(LLM은 호스트 PC가 대표 호출). P2P 참가자는 MAFIA1 텍스트 프로토콜로 동기화.
- **개인 통보**: 사람은 host_dm(🔒 [나에게만]), AI는 sys_prompt(`역할: {self.role}`).

## 4. 핵심 교훈 (재발 방지)

1. **런타임 계수는 import bind로 읽지 말 것** — `from mafia_config import NIGHT_SOLVE_SECONDS`는 테스트에서 값 변조가 반영 안 됨. `getattr(_cfg, "...")`으로 읽기.
2. **밤/투표 카운트다운은 데몬 스레드 `time.sleep`가 아니라 메인스레드 after 루프**로 — `root.after` 경합으로 resolve 누락이 발생함(실측).
3. **thinking 모델(Qwen3)은 `/no_thinking` system 지시 + content 필드만 반환** — `reasoning_content`를 대사로 취하면 "Thinking:"이 채팅으로 누출됨. `clean_llm_dialect` + `say` 이중 방어.
4. **Toplevel 팝업 금지** — 모든 팝업은 `_mafia_overlay_open` 임베디드 + dialogs 표준 스타일.
