# v6.42 — 남은 팝업/다이얼로그 전부 임베드화 (멤버 관리, 예/아니오 확인창) (2026-09-14)

## 계기

v6.41에서 큰 다이얼로그 4곳을 임베드로 바꾼 뒤, "이제 임베드 안 된 팝업이나
드롭다운 메뉴가 남아있는지" 점검을 요청받았다. 전체를 훑어 확인한 결과 세
그룹이 남아 있었다:

1. "그룹 멤버 초대" / "그룹 멤버 목록" 다이얼로그(여전히 Toplevel)
2. `messagebox.askyesno` 네이티브 예/아니오 확인창 3곳(그룹 나가기, 대화
   기록 삭제, 클립보드 파일 전송 확인) — Windows 기본 회색 대화상자라
   앱 테마와 어울리지 않음
3. `filedialog.askopenfilename`/`askdirectory` (파일/폴더 선택) — OS
   네이티브 피커라 구조적으로 임베드 대상이 아님(임베드하면 탐색기
   기능을 통째로 다시 만들어야 해서 오히려 나쁜 선택)

이번 회차에서 1번과 2번을 처리했고, 3번은 임베드하지 않는 게 맞다고
판단해 그대로 뒀다.

## 1. `_alert`/`_prompt_text`를 "parent 유무로 자동 분기"하는 디스패처로 전환

지금까지는 호출부마다 `_embed_alert`/`_embed_prompt_text`로 일일이
바꿔줘야 했는데, 이번엔 원래 함수 자체를 디스패처로 바꿔서 한 번에
정리했다.

- `_alert(title, message, kind="info", parent=None)`: `parent`가 없으면
  `_embed_alert`로, 있으면(다른 Toplevel 다이얼로그 안에서 여는 나머지
  경우) 기존 Toplevel 구현(`_alert_toplevel`로 이름을 바꿔 보존)으로
  위임.
- `_prompt_text(...)`도 동일한 패턴으로 `_prompt_text_toplevel`에 위임.
- 효과: 이 두 함수를 쓰던 **나머지 모든 호출부**(카테고리 이름, 파일
  오류, 입력 확인 등 다수)가 코드 한 줄도 안 건드리고 자동으로 임베드가
  됐다. 확인해보니 이제 `parent=`를 넘겨서 호출하는 곳이 전혀 없어서,
  `_alert_toplevel`/`_prompt_text_toplevel`은 안전망으로만 남아있는
  상태(죽은 코드지만 의도적으로 보존).
- `_rename_conversation_dialog`도 이 디스패처에 맞춰 자체 분기 로직을
  제거하고 단순화.

## 2. "그룹 멤버 초대"/"멤버 목록" 다이얼로그 임베드화

- `_open_member_dialog`(멤버 목록 — 대화방 헤더의 "멤버" 버튼 또는 ⚙
  설정 메뉴에서 진입)와 `_group_add_member_dialog`(멤버 목록 안의
  "＋ 멤버 추가" 버튼으로 진입하는 중첩 다이얼로그) 둘 다
  `_make_embed_dialog`로 전환.
- 전환 중 발견한 실질적 문제 2가지(그냥 Toplevel→Frame으로 바꾸기만
  했으면 런타임에 터졌을 것들):
  - `win.title(...)`, `win.grab_set()`처럼 **Toplevel에만 있는
    메서드**를 Frame에 호출하는 코드가 있었다. 특히 멤버 목록 안에서
    "별칭" 버튼을 눌러 대화 상대 별칭을 바꿀 때
    `self._rename_conversation_dialog(key, parent=win)`으로 자신을
    parent로 넘겼는데, `win`이 이제 Frame이라 `wm transient`가 Frame을
    master로 받지 못해 그대로 뒀으면 클릭 시 예외가 났을 것이다. →
    parent를 넘기지 않고 그냥 새 임베드로 열도록 수정(나중에 만든
    패널이 자동으로 위에 뜬다).
  - `win.protocol("WM_DELETE_WINDOW", ...)`도 Frame엔 없는 메서드 —
    제거하고 `_make_embed_dialog`가 반환하는 `_close()`로 통일.
- 두 다이얼로그를 동시에 열면(멤버 목록 위에 멤버 초대가 뜨는 중첩
  상황) 오버레이 2장이 겹겹이 쌓이는 구조인데, 마지막에 만든 패널이
  항상 위로 오므로 정상 동작함을 스크립트 테스트로 확인.

## 3. 네이티브 예/아니오 확인창 → `_embed_confirm`

- `dialogs.py`에 `_embed_confirm(title, message, kind="warning")`을
  새로 추가 — `_embed_alert`와 같은 틀(강조 아이콘 + 제목 + 본문)에
  [예]/[아니오] 버튼 두 개를 두고, Enter=예·Escape/닫기=아니오(되돌릴 수
  없는 작업이 대부분이라 안전한 쪽을 기본값으로)로 처리. 패널이 닫힐
  때까지 블로킹하며 True/False를 반환해 `messagebox.askyesno`와 동일한
  방식으로 호출부를 바꿀 수 있게 했다.
- 교체한 3곳:
  - `_leave_group_dialog` — 그룹 나가기 확인
  - `_delete_conversation_history_dialog` — 대화 기록 삭제 확인
  - `app.py` `_on_entry_paste` — 클립보드 파일(Ctrl+V) 전송 확인
- 더는 쓰이지 않게 된 `messagebox` 임포트를 `app.py`/`dialogs.py`에서
  제거.

## 검증

- `python -m py_compile` 전체 통과.
- `tests/test_headless.py` 재실행 — `ALL PASSED`.
- 스크립트로 실제 `App` 인스턴스를 띄워 `_open_member_dialog` →

  적으로 `invoke()`해서 `False`가 정확히 반환되는 것을 확인.
- 원격 스크린샷 캡처는 이번에도 창 위치가 겹치는 문제로 신뢰할 수
  없었어서, 코드 검토 + 예외 없음 + 반환값 검증으로 대체 확인했다.
