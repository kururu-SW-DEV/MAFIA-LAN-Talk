# v6.20 — 반응형 그리드, 닫기 버튼, 설정 메뉴 내장 (2026-09-13)

## 계기

v6.19에서 이모지/스티커 패널을 채팅창에 내장한 뒤, 실제 사용 화면(넓게 최대화한
창) 스크린샷을 받았다. 패널이 창 폭에 상관없이 항상 4~8열 고정이라 넓은 창에서는
가운데에 작게 몰려 있고 양옆이 텅 비어 보였다("그리드가 가운데 몰려있어"). 추가로
세 가지를 더 요청받았다: (1) 열 수를 창 크기에 맞춰 자동으로 늘어나게, (2) 패널에
X 버튼 또는 채팅창 빈 곳 클릭으로 끌 수 있게, (3) 설정(⚙) 버튼을 누르면 뜨는 메뉴도
별도 창이니 마찬가지로 내장해달라(모양·기능은 동일하게).

## (1) 반응형 그리드 — 창 폭에 맞춰 열 수 자동 조절

- **원인**: `EmojiPicker`의 이모지 그리드는 `_COLS = 8` 고정값을, 스티커 그리드는
  `cols = 4` 고정값을 그대로 썼다. v6.19에서 패널을 `fill="x"`로 채팅 영역 폭에 맞게
  늘어나도록 했지만, 그 안의 그리드 자체는 여전히 고정 열 수만큼만 채우고 나머지
  가로 공간은 그냥 `_reflow_inner()`가 가운데 정렬만 해줬을 뿐이라, 넓은 창에서는
  내용물이 작게 뭉쳐 가운데에 떠 있는 것처럼 보였다.
- **수정**: [widgets.py](widgets.py)에 `_emoji_pitch()`/`_sticker_pitch()`(칸 하나 +
  앞뒤 여백의 실제 픽셀 폭)와 `_cols_for(pitch)`(현재 캔버스 폭을 그 pitch로 나눈 몫)
  를 추가해, `_switch_cat()`/`_render_stickers()`가 그릴 때마다 열 수를 그때그때
  계산하도록 바꿨다. 캔버스 크기가 바뀔 때 이미 호출되고 있던 `_reflow_inner()`
  (가운데 정렬 담당)에 "지금 폭 기준으로 다시 계산한 열 수가 마지막으로 그렸을 때와
  다르면 현재 탭을 다시 그린다"는 로직을 추가해, 창을 늘리거나 줄일 때마다 그리드가
  자동으로 재배치되도록 했다. 최대 열 수에 인위적인 상한은 두지 않았다(요청이
  "창 크기에 맞춰 자동으로 늘어나게"였으므로 그대로 반영).
- **검증**: 실제 `App`을 생성해 창 폭을 450px→1400px로 늘렸을 때 스티커 열 수가
  2 → 13으로, 이모지 열 수가 5 → 27로 늘어나는 것을 헤드리스로 확인했고, 1200px
  창에서 실제로 스크린샷을 찍어 스티커 28개가 3줄(10열)로 넓게 펼쳐지는 것을
  육안으로도 확인했다.

## (2) 패널 닫기 — X 버튼 + 채팅창 클릭

- **수정**: 탭 바 맨 오른쪽에 닫기(✕) 라벨을 추가했다(다른 탭들과 달리
  `columnconfigure` weight를 주지 않아 늘어나지 않고 제 폭만 차지). 클릭하면
  `self.hide()`를 호출한다.
- **채팅창 클릭으로 닫기**: `app.py`의 `self.chat`(메시지 캔버스)에
  `<Button-1>`을 `add="+"`로 추가 바인딩해서, 패널이 열려 있을 때 채팅 영역 아무
  곳(빈 공간이든 메시지 위든)을 클릭하면 자동으로 닫히게 했다. 기존에 메시지
  클릭 시 클립보드 복사를 하는 태그 바인딩과는 별개로 추가된 것이라 서로 간섭하지
  않는다.
- **검증**: 헤드리스로 (a) X 라벨을 찾아 클릭 이벤트를 보내면 `is_visible()`이
  False가 되는지, (b) 패널을 다시 연 뒤 `self.chat`에 클릭 이벤트를 보내면 역시
  닫히는지 확인 — 통과.

## (3) 설정(⚙) 메뉴도 내장

- **배경**: `_open_room_more_menu()`(우측 상단 "⚙ 설정" 버튼)는 앱 전역에서 8곳
  넘게 재사용되는 공용 드롭다운 유틸리티 `_popup_menu()`(`dialogs.py`)를 그대로
  호출하고 있었는데, 이 유틸은 매번 `tk.Toplevel`을 새로 띄우는 방식이었다. 단,
  `_popup_menu()`는 메시지 우클릭 메뉴처럼 **커서 위치를 그대로 따라가야 하는**
  용도로도 널리 쓰이고 있어, 그 전부를 내장형으로 바꾸는 건 범위가 크고 실익도
  적다(우클릭 메뉴는 애초에 "커서 근처에 뜬다"는 동작 자체가 핵심이라 임베드할
  이유가 없다). 사용자가 명시적으로 지목한 "설정 메뉴" 한 곳만 범위로 좁혔다.
- **수정**: `_popup_menu(x, y, items, embed=False)`에 `embed` 매개변수를 추가했다.
  `embed=True`면 `tk.Toplevel` 대신 `tk.Frame`을 만들어 `self.root`의 자식으로
  `place()`(화면 좌표를 `self.root` 기준 상대 좌표로 변환하고, 본창 폭·높이를
  넘지 않도록 clamp)로 배치한다. 메뉴 항목을 그리는 코드(라벨 행, 구분선, 호버,
  클릭 시 닫기)는 Toplevel/Frame 버전이 완전히 동일한 함수를 공유해서 재사용하므로
  "모양과 기능은 동일하게"라는 요청대로 시각적으로 차이가 없다. 바깥 클릭 시
  닫히는 것도 동일하게 동작한다(`bind_all`로 Button-1/2/3 감시 — 기존 로직 그대로).
  `_open_room_more_menu()`와 `_open_add_menu()`(사이드바 [＋] 버튼)만
  `self._popup_menu(x, y, items, embed=True)`로 바꿨고, 다른 곳(우클릭 메뉴,
  자동 폭파 타이머 메뉴 등)은 그대로 뒀다.
- **검증**: 헤드리스로 `_open_room_more_menu()` 호출 전후 `root`의 자식 위젯
  목록을 비교해 새로 생긴 것이 `tk.Toplevel`이 아니라 `tk.Frame`이고 `place_info()`
  가 채워져 있는지(=place로 배치됐는지) 확인했고, 채팅 영역을 클릭하면 바깥 클릭
  처리로 정상적으로 닫히는지도 확인했다. 실제 화면 스크린샷으로 버튼 바로 아래에
  기존과 동일한 스타일(행 호버, 구분선)로 뜨는 것을 확인했다.
