# v6.5 앱 명칭 변경 (Lan Messenger → LAN Talk) (2026-09-13)

- **사용자 요청으로 브랜드명 일괄 변경**: "Lan Messenger"(오타로 "Lan Massenger"라고도 불림)에서
  **"LAN Talk"**으로 명칭을 바꿨다. 사용자에게 실제로 보이는 지점을 전부 찾아 바꾸는 작업이라,
  코드 곳곳에 흩어진 문자열을 놓치지 않는 게 관건이었다.
- **변경한 지점**:
  - `app.py`: 창 제목(`root.title`), 포트 충돌 시 시작 실패 안내 문구.
  - `lan_messenger.py`: 모듈 docstring 헤더, `argparse` 설명(description) 문자열.
  - `winapi.py`: Windows 토스트 알림·작업표시줄에 쓰이는 `APP_NAME`("LAN Talk")과
    AUMID 레지스트리 키 이름 `APP_AUMID`("LANTalk")를 함께 변경 — AUMID를 바꾸면 Windows
    입장에서는 사실상 새 앱으로 인식하므로, 기존 "LanMessenger" AUMID로 등록됐던 레지스트리
    항목은 그대로 방치되고(해로울 것 없음) 새 이름으로 새로 등록된다. 시작 메뉴 바로가기
    파일명도 `f"{APP_NAME}.lnk"`로 이미 동적으로 만들어지고 있어서 자동으로 `LAN Talk.lnk`가 됨.
  - 실행 런처 파일명: `START_Lan Messenger.bat` → `START_LAN Talk.bat`로 파일 자체를 새로 만들고
    구 파일은 삭제. 배치 파일 안의 `start "..."` 창 제목 힌트 문자열도 함께 맞춤. `winapi.py`가
    시작 메뉴 바로가기를 만들 때 참조하는 배치 파일 경로도 `f"START_{APP_NAME}.bat"`로 이름을
    상수에서 동적으로 조합하도록 고쳐서, 다음에 또 이름이 바뀌어도 이 부분은 저절로 따라가게 함.
  - `README.md`: 제목·실행 안내·파일 구성표의 현재 상태 설명은 새 이름으로 갱신. 단, 과거
    버전(v4.6 등)에서 "사내 메신저 → Lan Messenger로 개편했다"는 식의 **지난 변경 이력 서술은
    그대로 유지**했다 — 그 시점엔 실제로 그 이름이 맞았으므로, 역사 기록을 지금 이름으로
    소급해서 고치면 오히려 왜곡이 된다.
- **의도적으로 건드리지 않은 것**: `netutils.py`의 `default_datadir()`가 쓰는
  `%LOCALAPPDATA%\KariLanChat\` 폴더명은 그대로 뒀다. 이 이름은 "Lan Messenger"라는 브랜드명과
  글자 그대로 연결된 문자열이 아니라(더 오래된 별도 코드네임으로 추정) 이미 실사용 중인 사용자의
  대화 기록·설정·`secret.key`가 저장된 실제 데이터 폴더 경로이므로, 요청받지 않은 채 바꾸면
  기존 사용자 데이터가 "사라진 것처럼" 보이는 마이그레이션 리스크가 생긴다. 앱 이름과 데이터
  폴더명은 별개 문제로 분리해서, 사용자가 명시적으로 원할 때만 손대기로 함.
- 검증: `python -m py_compile`(변경 파일 전체) + `test_headless.py`/`smoke_gui.py`(창 제목이
  실제로 "LAN Talk"으로 뜨는지 확인)/`test_gui_flow.py` 3종 무인 테스트 전부 통과.
