# v1.20 — 최후변론 채팅 변론 표시 + 찬반 순서 재정렬 (2026-09-18)

## 사용자 지적
"최후변론할 때 채팅으로 변론할 기회없이 바로 처형여부로 가는건 이상해"

## 원인 (실측 확정)

1. **변론 말풍선이 채팅에 안 떴음(진원지)** — 변론 LLM을 백그라운드 워커에서
   돌린 뒤 `root.after(0, ...)`로 직접 UI 반영 — Tk 메인스레드 규칙 위반이라
   `RuntimeError: main thread is not in main loop` → 함수가 조용히 죽음
   (v1.17 유령방과 동일 패턴). 유저 눈엔 **찬반 팝업만** 뜸.
2. 순서 문제 — 찬반 팝업이 변론 발화와 **동시에** 뜨므로 변론을 읽을
   기회 자체가 사라진 구조.

## 조치 (v1.20)

| 항목 | 내용 |
|---|---|
| 변론 UI 큐 | LLM 응답을 UI 큐로 → **메인스레드 폴러(300ms)**가 채팅 말풍선 반영 |
| 순서 재정렬 | 변론문이 채팅에 뜬 '직후'에 AI 찬반 투표 개시 (변론 → 안내 → 찬반) |
| 유저 찬반 팝업 | 즉시 개봉하되, 유저는 변론을 읽으며 아무때나 찬성/만류 가능 |
| 안전망 | 기존 30초 후 기권(반대) 취급 강제 개표 유지 |
| 문구 교정 | "30초 안적" → "30초 이내" 오타 제거 |

## 실측 (E2E — 4인, 유저 생존)

```
개표 → 피고인 '김과장' 최후변론
→ after 2s: 변론 말풍선 채팅 렌더 확인(label '김과장')
→ 변론 반영 후 AI 찬반 표 투입 실측(지은 — '만류' 접수)
→ 유저 '만류' 클릭 접수 → 30초 안전망 이전 개표 불발 재현 OK
```

변론문이 채팅에 먼저 뜨고 팝업이 뒤따르는 순서 재확인.
컴파일 OK, 배포 30.05MB, 스모크 PASS.
